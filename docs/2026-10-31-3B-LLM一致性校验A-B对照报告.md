# 3B LLM 一致性校验 A/B 对照报告（ICD10CAP 万条语料）

> 日期：2026-10-31 ｜ 分支：codex-phase2-coding-mvp ｜ 模型：qwen2.5:3b-instruct（GPU，RTX 3060）
> 语料：ICD10CAP 万条字典题名（压力口径，度量链路能力，非临床精度）｜ 同环境、同规则、同分母，仅 LLM 维开关不同

## 一、结论先说

**3B LLM 维的排序税基本归零：万条 Top1 换码仅 15 条（0.15%），有推荐率零变化。**
上轮 0.5B 的 −79 条排序税（万条 JZEY 口径 6.1%）在本轮 3B 上未复现——模型升级达到了"承担一致性校验职责而不干扰排序"的目标。

| 口径（n=10000） | LLM-off（3B 关） | LLM-on（3B 开） | 变化 |
|---|---|---|---|
| 有推荐 | 9519（95.19%） | 9518（95.18%） | −1 |
| Top1 精确 | 9495（94.95%） | 9494（94.94%） | −1 |
| Top3 精确 | 9503（95.03%） | 9502（95.02%） | −1 |
| 类目 Top1 | 9503（95.03%） | 9502（95.02%） | −1 |

## 二、逐名 diff 明细

| 项 | 数量 | 说明 |
|---|---|---|
| Top1 换码 | **15**（0.15%） | 全部为同族/近义码间微调（如 I21.200X043→I21.205、F33.400→F33.400X001） |
| 仅 LLM-off 有推荐 | 13 | LLM 判据把这些候选打掉后无补位 |
| 仅 LLM-on 有推荐 | 0 | **LLM 未造成任何额外推荐**（无越权召回） |
| becameEmpty（丢期望码的清空） | 0 | **硬线达成** |

换码方向抽检：15 条里 LLM-on 给出的码多为**更细的扩展码**（X001 后缀、更精确的亚目），方向中性偏细——不构成系统性劣化。

## 三、与 0.5B 上轮的对照

| 指标 | 0.5B（10-09 报告，JZEY 口径） | 3B（本轮，ICD10CAP 口径） |
|---|---|---|
| Top1 换码率 | 16.1%（1215/7541） | **0.15%**（15/9519） |
| 排序税 | Top1 −5、净增益≈0（方向互抵） | −1（噪声级） |
| 证据引用维 | 恒 0 分（cited 恒空） | 正常参与（6/6 合法引用） |

**口径提醒**：两轮语料不同（JZEY 真实诊断名 vs ICD10CAP 字典题名），不能直接相减；但 16.1% → 0.15% 的换码率量级差异足以说明 0.5B 时代的排序扰动已消除。

## 五、过程中修复的环境问题（A/B 有效性保障）

1. **双 Ollama 安装冲突**：C 盘/D 盘两套 Ollama 各起 llama-server，GPU 显存瓜分、互相挤占 → 清杀至单实例；
2. **手搓 outbox 消息三连错**：message_type 应为 `coding.task.created`；payload.messageId 必须等于 outbox 行 id；payload.traceId 必须取该任务真实 pipeline_trace.trace_id（消费者按它校验）——已按正确口径重发；
3. **清库顺序**：medical_document → visit → patient 的 FK 顺序，且 case-entry resume 文件需删除防止跳过；
4. **本轮有效性问题**：首次 LLM-off 轮因 resume 跳过导致语料只有 8738 条且与 LLM-on 分母不一致——已作废并全量重导（10000 条）后重跑，两轮分母完全一致。

## 六、后续动作建议

1. **LLM 维恢复参与排序**：排序税归零 + 引用维可得分，建议恢复 LLM-on 作为默认配置（当前已默认开启）；
2. **JZEY 万条真实口径复测**：ICD10CAP 是压力语料，临床口语语料上的排序影响需再跑一轮 JZEY（跑批脚本与本轮相同，语料切换 input_ids 即可）；
3. **审计留痕**：手搓 outbox 属一次性运维操作，脚本已归档 `scripts/requeue_outbox_v4.sql`（正确口径模板），不再复用错误版本。
