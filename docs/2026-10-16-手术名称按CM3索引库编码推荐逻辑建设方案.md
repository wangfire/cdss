# 手术名称按 CM3 索引库的编码推荐逻辑建设方案

> 日期：2026-10-16　状态：**方案待拍板，未开工**
> 参照实现：诊断侧 ICD 索引两段式链路（`src/HospitalAi.Application/Coding/IcdIndex/*`）
> 参照文档：`docs/2026-10-09-见与另见索引规则梳理与现有逻辑对照方案.md`、`docs/2026-10-08-精度验收口径规范.md`
> 本方案里所有数字都是 2026-10-16 对本地 `HospitalAi` 库与现网代码实测所得，非引用旧稿。

## 0. 一句话口径

**手术名称 → 在 `cm3_index` 里先召回主导词（0 级行，即术式动作词）→ 只在该主导词所属子树内逐层匹配修饰词（部位 / 入路 / 术式方式 / 伴次 / 用途）→ 取链路终点（或最近带码祖先）的索引编码 → 按前缀展开成手术字典 `medical_code` 的细码 → 与既有通道平权参与打分 → 推荐出 ICD-9-CM-3 手术操作编码。**

这与诊断侧「主导词命中后才去该主导词下配修饰词」是同一条纪律的两个实例，不是新发明一套逻辑。

## 2. 数据事实：`cm3_index` 与诊断索引的同与异

### 2.1 结构（19671 行）

| level | 行数 | 带码行数 |
|---|---|---|
| 0（主导词） | 2855 | 1870 |
| 1 | 7189 | 6272 |
| 2 | 6129 | 5561 |
| 3 | 2456 | 2249 |
| 4 | 816 | 750 |
| 5 | 197 | 184 |
| 6 | 27 | 27 |
| 7 | 2 | 0 |

- `index_level = 0` 与 `parent_seq_no = 0` **完全等价**（双向差集为 0）；无 NULL 父。
- **68% 的主导词（1945/2855）没有任何子节点**，其中 1391 条自带编码 → 对手术索引来说，**「主导词命中即终点」是常态**，下钻只发生在 910 个有子树的主导词上。这与 ICD 诊断索引（主导词是疾病名词、几乎都要靠下钻定细码）形态不同，直接决定第 6.3 节的评分与席位设计。
- `raw_name_en` 非空率 **100%**（各级全满，是真英文索引原文），诊断侧该列在匹配链路里**根本没被投影进 `IcdIndexRow`**（`IcdIndexModels.cs:6-12`）。手术名称里英文术式名与器械/术式缩写（Abbe 手术、AESOP、Z-  plasmin）真实存在，**CM3 侧必须用上这一列**（见 6.2）。

### 2.2 `lead_word_status` 语义（本轮实测确认）

| status | 行数 | 含「见」 | 空码 | 在 0 级 |
|---|---|---|---|---|
| 0 | 19139 | 1096 | 712 | 154 |
| 1 | 532 | **532（100%）** | **532（100%）** | **532（100%）** |

`lead_word_status = 1` 就是**「本行不是有效主导词，是 见 指针行」**——三个条件 100% 同时成立，与诊断侧靠 `JumpKind` 推导等价。

但**不能只信列**：0 级含「见」的行共 **686** 条，其中 **154 条列标为 0**（有效）。所以主导词有效性的判据必须**词面判定为主、列为辅、二者不一致时以词面为准并记台账**，这正是诊断侧纪律 1「只登记指针、不剥词面」的同族问题。

### 2.3 指针与修饰形态（`raw_name` 命中行 / 其中 0 级）

| 形态 | 行数 | 0 级 | 对 CM3 的含义 |
|---|---|---|---|
| `见` | 1628 | 686 | 主导词级指针 + 深层修饰词指针 |
| `另见` | 413 | 142 | 同诊断侧另见语义 |
| `―见`（U+2015 一字线为实际书写） | 1204 | 543 | 指针段前缀是**一字线**，不是 ASCII `-`；正则照抄诊断侧会漏 1204 条 |
| ASCII `-见` / 全角 `－见` | 各 1 | 0 | 实测可忽略 |
| `（另见` / `(另见` | **0** | — | **诊断侧 M1 的括号形态指针在 CM3 不存在**，`ParenJumpRegex` 不迁移 |
| `又称` / `现译名` | **0** | — | **M9 等价译名、M2 现译名改道在 CM3 没有对象**，不落地 |
| `NEC` | 1183 | 84 | 裸写，无 `NEC)` 括号形态（0 行）；`NecTokenRegex` 可直接复用 |
| `NOS` | 81 | 7 | 同上 |
| `伴` | 1229 | 67 | 伴次手术，对应 `――伴` 连接子树（见 2.4） |

### 2.4 码形：与 ICD-10 完全不同构

| 形态 | 行数 | distinct | 例 |
|---|---|---|---|
| `NN.NN`（4 位书码） | 15230 | 3460 | `70.61`、`45.90`、`86.04` |
| `NN.N`（亚目 1 位） | 1683 | 270 | `17.4`、`59.5`、`75.0` |
| 含 `[` / 区间 / 星剑号 | **0** | — | 码列干净 |

- 索引码 distinct **3730**。
- **字典侧**：`code_system_code = 'ICD-9-CM-3'` 有 14388 个 distinct 码（两个院各存一份，共 28776 行），码形是带点长码 `00.0100`、`00.0200X001`、`17.4100`，点恒在第 3 位。
- **前缀展开按 `index_code` 字面长度取前缀**（`LEFT(dict.code, LEN(index_code))`）时：3730 个索引码里只有 **3 个**落不到字典（`37.17`、`40.92`、`64.69`）——覆盖率 99.9%。（注：若固定按 5 字前缀匹配会假报 273 个不命中，全部是 `NN.N` 亚目形，属于谓词写法错误，不是数据缺口。）
- 反向可达：14388 个字典码中 12462 个（86.6%）能被某个索引码前缀到达；**索引码与字典码精确相等只有 2 个**——即**索引给出的码永远不是终码，必须展开**，这一点与诊断侧「类目→细码」同构，但形态是纯数字。
- 展开扇出（每个索引码展开成多少细码）：1 码 1085 个前缀、2 码 799、3–5 码 1003、6–20 码 529、>20 码 41，最大 **154**，均值 **7.2**。→ 必须有每族展开上限与族内排序（6.5.4）。

## 3. 目标与非目标

**目标**
1. 手术名称输入产出 `RecommendationType = PROCEDURE` 的推荐，码形为字典细码（`##.####` / `##.####X###`）。
2. 匹配逻辑严格两段式：先主导词（0 级），命中后才在该主导词子树内配修饰词；不允许跨主导词的修饰词自由拼接。
3. 精度优先于召回：**空推荐好过错推荐**——与诊断侧硬线一致（`becameEmpty` 只计「丢了期望码的清空」）。
4. 有可复跑的万条级手术回归台账与三关验收，任何一步能量化。

**非目标（本轮不做）**
- 不做手术编码的**自动终审**（是否需与诊断/手术次序联动、是否需要主刀填的码做对照，属病案业务，另行拍板）。
- 不复制 M6/M7（括号语义赌博、逗号尾段锚点）——它们在诊断侧已被实测否决，CM3 词面形态更简单（无括号指针），照抄只会引入新风险。
- 不做 M9（又称）与现译名改道：CM3 库里 0 条，无对象。
- 不动星号/剑号、形态学码 `M\d{4}/\d`、肿瘤部位码：ICD-9-CM-3 无这些形态（2.4 实测 0 行）。

## 4. 总体架构

```
                 ┌──────────────────────────────────────────────┐
源库首页手术 ──▶ │ 输入段：coding_diagnosis_input                │  B0
                 │ SourceType=OPERATION + 顺序 + 原文/归一        │
                 └──────────────────┬───────────────────────────┘
                                    ▼
   cm3_index ──▶ ICm3IndexSource ──▶ Cm3IndexSnapshot ──▶ Cm3ProcedureIndexMatcher
                 ( Ef…, 单例+信号量 )  Leads/Redirects/      ① 主导词召回(0级)
                                       Alias/LeadByExactKey   ② 子树内修饰词下钻
                                                             ③ 指针改道(见/另见/见亚目)
                                                              ▼
                    Cm3CodeExpander ──▶ 索引码→字典细码前缀展开（NN.NN / NN.N / 方括号双码）
                                                              ▼
                    管道 Step 6.7 合并：与 Exact/BM25/向量候选按平权打分 → 席位 → 落库
                                                              ▼
                    coding_recommendation (PROCEDURE) + recommendation_evidence(SourceType="CM3_INDEX")

```

分层原则照抄诊断侧：**Application 层放纯逻辑（可单测、不碰 EF）；Infrastructure 层只负责把表读成行；Worker 管道只做装配与降级；Api 只管读写与失效。**

## 6. 匹配逻辑（核心）

### 6.1 输入规范化

复用 `TextMatch.NormalizeKey`（去标点空白、小写、罗马数字折叠，`TextMatch.cs:29-56`），在此之上加手术侧两步：

1. **去已有编码**：医生在手术名后自填的 `（99.9200）` 之类必须剥掉（诊断侧同规则在 `ClinicalFactExtractor.cs:109`），否则数字会污染字符覆盖率。
2. **术式中心词识别 + 状语剥离**：手术名称是「部位 + 入路 + 方式 + 术式」的自由语序短语（`腹腔镜下胆囊切除术` / `胆囊切除术（腹腔镜）` / `经口内镜下肌切开术`）。主导词是**术式动作名词**（切除术/吻合术/修补术/置入术/引流术…），不是部位。这一步产出 `(术式候选, 修饰词集合)`，修饰词集合参与 6.3 的下钻增益与门控，**不参与 6.2 的主导词召回锚定**（否则又回到诊断侧纪律 6「部位尾段抢召回名额」的坑）。

> 拍板项 Q1：术式中心词表是否用 `cm3_index` 的 2323 条有效主导词自动构建（词面尾读「术/置入/切除…」），还是先手工维护一份 200–300 的高频术式族表。**建议后者起步、前者做覆盖率核对。**

### 6.2 主导词召回（只认 0 级）

- 候选集合 = `index_level == 0` 且**有效主导词**（`lead_word_status == 0` 且词面无 `见/另见` 指针；两者不一致按 2.2 以词面为准并记台账）。指针行单独进 `Redirects` 键空间，等价诊断侧 `IcdIndexSnapshotBuilder` 的 `:166-168` + `:210-227`。
- 别名与权重：沿用诊断侧口径（首段 1.0、后续段 0.85、方括号内 0.85、`NEC/NOS` 剥离）。CM3 的 0 级词面常见 `凹陷,巩膜,用于环扎术―另见环扎术,巩膜的14.49` 这类「主导词,部位,用途」逗号多段，拆段规则可直接复用 `ParseAliases`。
- 匹配判据：**复用 `TextMatch.MatchesInput` 的 `Ratio ≥ 0.6` 且（`MaxSegment ≥ 3` 或 `Ratio ≥ 1.0`），≤2 字 key 要求全包含**（`TextMatch.cs:156-166`）。这是诊断侧已验证的连续覆盖门控，CM3 不重新调参起步。
- 名额：`LeadWordTopK = 8`（`V22PipelineOptions.cs:29`）起步；排序沿用 `CoveredChars → CoverRatio × Weight`（`IcdIndexMatcher.cs:217-221`）。
- **`raw_name_en` 作为第二召回面**：中文召不回时用英文索引名召回，权重不高于中文（拍板项 Q2：建议英文命中只在无中文命中时补位，不参与主排序，避免 `Abbe operation` 与 `Abbe 手术` 双占名额）。
- 全空时：先做一次 `Redirects` 改道重试（对标 `Resolver:240-246`），再退到单字精确主导词（`:221-235`）；**不做字典兜底**（诊断侧 `Resolver:41-43` 的「召不回即空」口径保持）。

### 6.3 修饰词下钻（只在该主导词子树内）

复用诊断侧机制，逐条对应：

| 诊断侧 | CM3 取值 |
|---|---|
| 子节点 + 连接行穿透（`Matcher:111-133`，`MaxConnectorLookThrough = 2`） | 同，`――与`/`――伴` 透明化（2.5 实测就是这两类） |
| 进入门槛 `gain ≥ 1`（新增覆盖字符） | 同 |
| 断链条件 `bestGain < 1` 即停 | 同 |
| `depthBoost = 1 + 0.05 × 证据路径长度`（`Resolver:541-545`） | 同 |
| `pathOverlap < 0.30` 丢弃（`:549-552`） | 起步同值，专台台账后再评估 |
| 码取终端行，否则最近带码祖先（`:674-690`） | 同；**祖先回退必须记证据**，因为 CM3 的 68% 主导词是死路，回退频率与 ICD 不同分布 |
| 每族席位 `MaxSeatsPerIndexFamily = 1`（`Resolver:150-208`） | 同；这一条是诊断侧纪律 9 里点名未解决的坑（同族挤占精确码名额），CM3 扇出均值 7.2、最大 154，**必须一开始就限族**，不留到线上 |

CM3 特有的一处：**带码死路主导词（1391 条）命中即产出**，此时 `IndexTitleDepth` 应为 0 并保留，不能因为「没下钻」被判为弱证据——建议这类行的分数惩罚系数取 `1.0`，而诊断侧的 `IsIndexFallback → 0.8` 只用于祖先回退。

### 6.4 指针改道（CM3 实测的四种形态）

| 形态 | 实测条数 | 处理 |
|---|---|---|
| 0 级 `X ―见 Y`（主导词指针，空码） | 532（+154 未标记） | 等价诊断侧 **见-1 强制改道**：本行不得自码对抗，改到 `Y` 主导词重走 6.2/6.3；改道目标平权入池，不加权（纪律 3） |
| 深层 `―肠―另见吻合术,肠`（带码行内指针） | 413 含另见，其中深层 271 | 等价 **另见-1**：本行带码→病案信息简单时用本行码，信息更详细时转指针树取细码；实现沿用 `SeeAlsoHints` 只填空位（纪律：末位让位实测挤掉既有候选，被否决） |
| `―见亚目 17.4`（指向**编码亚目**而非主导词） | 属 1683 行 `NN.N` 码族 | **CM3 新增形态，诊断侧没有**：目标是编码而不是词，改道应落到 6.5 的前缀展开（`17.4` → `17.4*` 细码族），不得再当主导词去召回 |

改道失败的处置：指针行本身无码（532 条 100% 空码），**改道不成功即该候选丢弃**，不允许「保留指针行当候选」；但必须计入 `becameEmpty` 台账，因为 602/686 的目标本身也可能断链（诊断侧纪律 9 的「知识库覆盖缺口」豁免口径在这里同样适用，需逐条列名与所丢码）。

### 6.5 索引码 → 手术字典细码的展开

1. **前缀规则按字面长度**：`NN.NN → LEFT(code,5)`，`NN.N → LEFT(code,4)`。这是 99.9% 覆盖的关键（2.4）；固定 5 位前缀是错的。
2. **门控沿用诊断侧**：`GateRatio 0.6 / GateMaxSegment 3`、`WholeTitleMinInputRatio 0.75`、整标题字面命中给 `1.0`、回退分 `0.55`（`IndexCodeExpander.cs:72-78, 401-443`）。手术名称的整标题命中尤其值钱：`胆囊切除术` 直接命中细码标题即为强证据。
3. **方括号双码 `57.87[45.51]`**：109 行，`index_code` 全 NULL，即当前完全丢失。规则：从 `raw_name` 解析 `主码[附加码]`，**主码进常规展开，附加码作为伴次/条件码**，语义对标诊断侧 `Conditional` 的「触发分下限 0.62、附加码分上限 0.72、`IsConditionalAddOn`」（`IndexCodeExpander.cs:291-320`），不并列成两条一等候选。拍板项 Q3：是否所有 `[..]` 都作附加码（另有一种是「部位码换写法」），需 109 行人工过一遍再定，**先只解析、不出码**，避免拿语义赌博（纪律 5）。
4. **扇出控制**：单索引码最多展开 `MaxExpandedCodes = 3`（对标诊断侧 `Expand → Take(maxResults) = 3`，`:108`），族内按细码标题对输入的覆盖率排序；>20 扇出的 41 个前缀（含最大 154）必须靠这条挡住，否则一个 `86.04` 就能吃掉整条推荐。
5. **码表脏数据**：`37.17 / 40.92 / 64.69` 三个索引码在字典无前缀命中 → 属知识库覆盖缺口，进 E 类排除台账（口径规范里的冻结剔除），不为此加匹配器判据。

### 6.6 打分、席位与降级

- **平权入池**：CM3 索引候选以权重 1.0 进常规候选池，由覆盖率/整标题贴合度裁决，**不做「不低于其他通道」的加权**（诊断侧 M2 实测：加权让万条 173 条补位改写了 250 条 Top1）。
- `RecallChannel = "CM3_INDEX"`，证据行 `SourceType = "CM3_INDEX"`，证据文案给 `主导词 → 修饰词 → …` 路径（复用 `pathDisplay` 的 `→` 拼接，`Resolver:504-508`）。
- 七维权重复用：Exact .15 / Semantic .15 / Retrieval .10 / Rerank .10 / Rule .15 / Evidence .20 / LLM .15（`ScoringOptions.cs:15-27`），缺失维重归一。
- LLM 一致性校验通道**必须同步认识 CM3 候选**：`LlmConsistencyJudge` 的 `CandidateExistsInRetrieval` 校验「模型回显码在该输入的检索池里」，池子必须包含 CM3 展开后的细码，否则手术侧 `LlmScore` 恒被误判（新落地的第 7 维不能上线成假绿灯）。
- 每输入最终仍取 `MaxCandidatesPerInput = 3`（`V22PipelineOptions.cs:23`），排序沿用 `IndexTitleDepth → Final`（`Runner:814-818`）。
- 降级：快照加载失败 → 记 `DEGRADED.NO_CM3_INDEX`，手术侧**退回今天的 Exact+BM25**（与诊断侧「索引失败即无字典兜底」不同，这里字典通道本来就在，属于纯增量，不构成回归风险）。

**关 3　硬线 `becameEmpty = 0`**
口径与诊断侧一致：只计「丢了期望码的清空」。纯噪声清空需豁免，但豁免必须附两样东西——逐条列出打空名与所丢码，以及 `--pblank` 的归因落在「子树无码/链路无终点」这类知识库缺口；若落进新的空档，说明改动本身有问题。

- L1 修饰齐全：部位/入路/方式都在索引链路里。
- L2 联合/双码：`主[附]` 形态，判主码族。
- E-P1 噪声名：`运动训练`、`穴位贴敷治疗` 这类康复/中医项（源库样例），单列不入精度分母，先建**专项台账**。
