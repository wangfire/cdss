## 二、完善方案（五个工作包，合计约 4 天）

### WP-A｜医院下拉登录（后端 + 前端，1 天）

1. **后端**：新增匿名端点 `GET /api/v1/hospitals/public`（**无授权**，仅返回 `id + code + name` 三字段，不泄露其他信息；加内存缓存 60s 防刷）——登录页在未认证状态下必须能拉到医院列表；
2. **前端 Login.vue**：hospitalId 文本框改为下拉（options 来自 public 端点，显示 `name (code)`，值为 id），保留手动输入回退（下拉底部"手动输入…"）；删除 GUID 正则校验（下拉值天然合法）；
3. **i18n**：login.ts 补 `hospitalSelect` / `hospitalManualInput` 等 key；
4. **验收**：清空 localStorage → 登录页下拉可见医院 → 选择后登录成功。

### WP-B｜工作台服务端分页（后端 + 前端，1.5 天）

1. **后端**：`GET /api/v1/workbench/tasks` 加 `page`（默认 1）、`pageSize`（默认 20，上限 100）、`keyword`（姓名/病案号 LIKE，**数据库端过滤**）参数；返回 `{ total, page, pageSize, items }`；保留 `status` 过滤；
2. **契约**：`WorkbenchTasksResponse` 增加分页字段（向后兼容：无参数时行为不变，前端切换后再移除全量路径）；
3. **前端 workbench.ts + Workbench.vue**：搜索框防抖 300ms 触发服务端查询；分页条替换客户端切片；移除"一次拉 5000 条"逻辑与相关特判；
4. **验收**：万条任务库上翻页/搜索响应 < 500ms；客户端内存不再持有全量任务。

### WP-C｜通知中心去 mock（前端，0.5 天）

**建议方案：本地会话通知（推荐）**——当前系统无推送基础设施（无 SignalR/轮询事件源），真实"通知"场景（审核完成、任务失败）由页面内 toast 已覆盖。因此：
1. 移除 `mockNotifications` 假数据，store 改为**空初始化**；
2. 保留通知中心组件与交互框架（标记已读/全部已读/清除），作为后续接入真实事件的容器；
3. 顶栏铃铛**无未读时隐藏红点**（现有逻辑已支持）；
4. `actionUrl` 跳转保留（后续事件可携带）；
5. 验收：登录后铃铛无假数据；不出现"张三注册"等测试残留。
（备选：如院方要求站内信，属新需求另立项，不在本次生产化范围。）

### WP-D｜i18n 收口（前端，1.5 天）

1. **扫描**：脚本枚举 231 行硬编码中文，按文件分桶产出清单；
2. **优先级**：先收口用户可见高频路径（错误 toast / window.confirm / 表单标题 / 删除确认），静态布局文案次之；
3. **方式**：逐条迁入 `locales/zh-CN + en-US` 对应模块（knowledge/workbench/caseEntry 等），代码替换为 `t('key')`；
4. **防回潮**：CI 加 eslint 规则（`vue-i18n/no-raw-text`）对 `<template>` 中文文本报警；
5. **验收**：typecheck 通过 + 切换英文界面无中文残留（抽样五大页面）。

### WP-E｜去外链头像（前端，0.5 天）

1. **新组件 `UserAvatar.vue`**：本地内联 SVG——按用户名 hash 取色 + 首字母（中文名取末字），无任何外链请求；
2. **替换**：`stores/user.ts` 的 defaultAvatar 改为返回 `{ initials, colorClass }` 或组件 prop；DashboardLayout 4 处 + Dashboard 1 处引用替换；
3. **验收**：断网环境头像正常显示；无 dicebear 域名请求。
