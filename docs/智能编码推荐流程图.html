智能编码推荐：系统是怎么"想"出一个 ICD 码的

面向病案编码员 · 每一步都对应你手工编码时的一个动作 · 数据口径见文末（2026-10-15）

一句话：系统做的就是你翻 ICD 索引书的那套动作 —— 定主导词 → 逐级往下钻 → 把索引行上的码展开成可用码 → 再和字典精确命中、全文检索、语义近义的结果放一起比 → 打分取前 3 → 告诉你"为什么是这个码"。

1收料：把这一份病案要编码的条目收齐

对应动作：拿到首页和病历，先看有多少条要编

  • 来源：首页出院诊断、首页入院诊断、手术操作，以及病历文书里自动抽取的诊断
  • 清洗：去掉序号、"可能性大 / 待查"这类连接噪声；识别侧别与部位（左/右/双侧）、病程（急性/慢性）、否定（已排除）
  • 同一条诊断在首页和文书里都出现时，只编一次，优先采用首页写法
▼

2体检：这份病案现在能编吗

对应动作：发现缺页、时间矛盾，先退回临床而不是硬编

  • 检查：文书是否存在且非空、是否重复提交、出入院时间是否自相矛盾
  • 不合格 → 标记「需人工处理」，本次不出推荐结果（不会给一个"差不多"的码）
▼
分流：这一条是"诊断"还是"手术操作"？
诊断 → 走 ICD 索引书通道（下面第 3 步为主），再加语义近义检索补充
手术操作 → 走操作字典通道（ICD-9-C3 卷三），以同名/同义词精确命中 + 全文检索为主；诊断码不会混进来
▼

3查索引书：内置一本 5.1 万行的 ICD 索引，分四小步

对应动作：定主导词 → 翻子目录 → 抄下条目码 → 实在没有才用"病，疾病"

3.1 定主导词（翻到哪一页）词条的主词、别名、括号异体都拿去和你的诊断名匹配，别名要在诊断名里真的出现（去标点、等义词换算后按字序比）；泛词（动脉 / 慢性 / 综合征…）不许当锚点；写法不同的等义词先换算（霉菌病 = 真菌病、乳房 = 乳腺、癫癎 = 癫痫）；最多同时试 8 个主导词。
3.2 逐级下钻（子目录里找更细）子节点必须带来输入的新字符（≥2 个）才往下走；部位门控（输入的"腰椎"不会被带到"颈椎"分支）；急性 ↔ 慢性、近期 ↔ 陈旧不跨分支；碰到"见 / 另见"按索引书改道，且与下钻比较谁覆盖输入更多；整条链路对输入的覆盖不足 30% 直接丢弃。
3.3 展开编码（条目码变成可用码）认 7 种索引写法（类目码、横线详码、星号剑号、范围、替代组…），通过本地 ICD 字典展开：字典标题要连续覆盖诊断名 ≥60% 才算这个码成立；肿瘤形态学码（M8000/3 这类只说性质不说部位）另查肿瘤部位表补出部位码。
3.4 末位兜底（实在找不到）所有具体主导词都落空时，才走"见情况"翻泛词 病，疾病 / 疾患；这类推荐会显式标注「兜底」并降权（×0.8），永远排在具体链路之后。
  • 索引行上写的码在字典里展不开时：只推荐索引码本身并标注「回退」，让编码员知情，而不是编一个看起来对的码
▼

4另外三路一起找，结果并到一起（同一个码只留一条）

对应动作：不只翻索引，也会对着字典和历史病案再核一遍

字典精确命中名称完全同名、或命中已登记的同义词 → 直接进候选，分数最高一档
全文检索对着编码知识库全文找相似标题；要求连续覆盖 ≥0.6 且最长公共段 ≥3 字才保留（治"神经根型腰椎病 → 糖尿病腰骶神经根病"这类字面像、临床不对）
语义近义检索找"说法不同、意思相同"的标题（术后状态、化疗后这类跨表述）；只在诊断通道启用
▼

5排序打分：谁更像这个诊断

对应动作：把几个候选摆一起，挑最贴合的那一个

  • 先由模型对池内前 8 条做精排，再按七个维度加权：完全同名、语义相近、检索命中、模型精排、规则校验、病历证据、大模型复核
  • 证据维度权重最高：推荐必须能在病历原文里找到支撑段落
  • 一族一席：同一索引族（同一类目下的近亲码）只占一个位置，避免 3 个候选全是同一个码的变体
  • 每条诊断最多交付 3 条候选 —— 精度优先，宁少不错
▼
6 · 结论分档：这条推荐敢不敢直接用？
高置信（建议直接采用）：总分 ≥0.85、有病历证据支撑、且明显领先第二名
需人工复核：第 2、3 名一律需复核；或证据不足、领先不明显、规则只给了部分放行
不给推荐：没有安全候选就空着 —— 空推荐好过错推荐
▼

7编码员在工作台看到的

  • 编码 + 名称 + 分数 + 置信度档位，每条都带推理路径：主导词 → 修饰词 → 索引节点 → 最终编码，以及是"具体链路 / 兜底 / 回退"哪一种
  • 带病历原文证据段落，可直接核对依据，不是黑箱
  • 你已确认的编码在系统重跑时不会被覆盖；系统再次运行只会把旧推荐转成「历史版本」
  • 任一条不满意都能查"是哪一步没走通"（召回？下钻？字典展开？），可复现、可反馈

案例速查：一条推荐的结果分四档，怎么读

下面 9 个案例全部取自 1 万条真实临床诊断名的回归台账（2026-10-14 版本），"病案编码"就是病案里实际用的码。这一版在口径内 6,760 条（其余按验收口径的剔除判据不计）上的分布是：Top-1 精确命中 1,516 · 类目命中但码不同 1,052 · 有推荐但类目不对 3,177 · 无推荐 1,015；按全部 1 万条统计则是 1,945 / 1,319 / 4,099 / 2,637。

① Top-1 命中 = 第一选择就是病案码 ② 类目命中 = 三位数类目对了，后面一两位不同 ③ 有推荐但类目不对 = 需要人工换码 ④ 无推荐 = 系统主动留白，不猜

病历原文系统给的病案编码实测归因怎么读 / 怎么修
1 型呼衰原因待查 无推荐 J96.900 未特指的呼吸衰竭 只召回到泛词主导词 原因，它的子层是 外部，全身性效应 T75.8、未述及(疾病) R69，钻不出可用码 → 0 条。同一条写成"呼吸衰竭"就能走通：衰竭(全身 NEC) → 呼吸 = J96.9 → 展开 J96.900X001 / X002 / X003 "呼衰"是简称，索引书里没有这一页 —— 属词汇缺口。修法：补等义词（呼衰 = 呼吸衰竭），或请临床写全称。空推荐好过错推荐，所以系统选择留白。

口径提示：诊断侧不做字典名直匹配兜底，编码只能来自索引链路或检索通道，所以"字典里有这个码"不等于"系统能推荐它"。规则改动一律先过万名离线回归，硬线是不允许任何一条输入因为改动而失去推荐。想复核上表任意一条：离线诊断工具（tools/IcdIndexDiag）能逐名打印"召回了哪些主导词、每个子层为什么被剔除、最终展开成哪些码"，把诊断名发给开发即可复现。
