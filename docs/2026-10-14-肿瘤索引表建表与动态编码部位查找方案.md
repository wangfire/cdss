# 肿瘤索引表建表与动态编码部位查找方案（2026-10-14）

## 1. 现状结论（先核对了库和代码）

- `icd_index`（51268 行）**已含癌形态学树**：1908 行 `index_code LIKE 'M%/%'`，且层级与索引书一致，例如：
  - seq 143 `癌 - 另见 肿瘤，恶性 | M8010/3`（主导词）
  - seq 144 `－C细胞 | M8510/3`
  - seq 145 `－－特指部位 - 见 肿瘤，恶性 | NULL`
  - seq 146 `－－未特指部位 | C73`
- 但 **"肿瘤，肿瘤性"部位表（本次 Excel 的内容）不在库里**——`index_level=0` 无 肿瘤 主导词。所有 `见 肿瘤，恶性` 指针目前都是死路。
- 代码侧的"过滤"发生在 `IndexCodeExpander`：
  - `M8332/3:C73` 这种**索引自带部位码**的形态学码 → 已按 `SiteCode` 展开（正确，无需查肿瘤表）；
  - 裸形态学码 `M8510/3`（无部位）→ `BareMorphologyRegex` 直接丢弃（IndexCodeExpander.cs:466-498），宁缺不滥。
- 因此本方案要补的就是：**部位表入库 + 裸 M 码的"行为码→部位码"查找通道**，其余现有行为不变。

## 3. 表结构 DDL

平台级共享表（同 `icd_index`，不带 hospital_id）。一行 = 索引书一行，五个动态码并排存列，行为码→列的映射放在代码里而不是拍平成行，避免 5 倍行数和导入歧义。

```sql
CREATE TABLE dbo.tumor_index (
    id                  uniqueidentifier not null default newid() primary key,
    seq_no              int            not null,  -- 导入顺序号，父链用
    index_name          nvarchar(200)  not null,  -- 中文词条（trim 后，保留 NEC/#/◇ 与括号）
    index_name_en       nvarchar(200)  null,
    index_level         int            not null,  -- 0~4，由行首 － 个数判定
    parent_seq_no       int            not null,  -- 0=根
    full_index_name     nvarchar(300)  not null,  -- 父链拼接全路径（甲状腺 行 = "肿瘤，肿瘤性 甲状(腺)"）
    code_malignant_primary   nvarchar(20) null,   -- 恶性-原发（/3、/9）
    code_malignant_secondary nvarchar(20) null,   -- 恶性-继发（/6）
    code_in_situ             nvarchar(20) null,   -- 原位（/2）
    code_benign              nvarchar(20) null,   -- 良性（/0）
    code_uncertain           nvarchar(20) null,   -- 动态未定或未知（/1）
    jump_kind           int            not null default 0,  -- 0无 1见 2另见（复用 IndexJumpKind 语义）
    jump_target         nvarchar(200)  null,      -- "肿瘤，窦" 等，目标在本表内
    is_deleted          bit not null default 0,
    created_at / updated_at ...                   -- 与 ConfigureCommonProperties 对齐
);
CREATE UNIQUE INDEX ux_tumor_index_seq_no ON dbo.tumor_index(seq_no);
CREATE INDEX ix_tumor_index_parent ON dbo.tumor_index(parent_seq_no);
```

设计取舍：
- **不并入 icd_index**：码列语义完全不同（1 列 vs 5 列），且主导词树/快照构建按单树假设；单独表 + 单独快照最干净，也符合"肿瘤索引单独建索引表"的要求。
- 五列并排而非 (行为码, 部位码) 长表：Excel 天然一行五码，导入零歧义；查询按行为码取列是一次属性访问。
- `full_index_name` 预生成，消歧与展示都用它。

## 4. 导入方案

沿用 `icd_index` 的导入配方（Python 解析 → TSV → sqlcmd/批量 INSERT，seed 带 BOM，`HOSPITAL_AI_CONNECTION_STRING` 指 localhost/sa）：

1. 跳过前 2 行表头；行循环：
   - `index_level` = 行首连续 `－`（兼容 `—`/`-`）个数；`parent_seq_no` 用层级栈维护；
   - trim 词条与五个码（`'C73  '`→`C73`）；码统一大写；
   - `- 见 X` / `- 另见 X` 段解析进 `jump_kind/jump_target`（词面保留原文，与 icd_index 快照解析兼容）；
   - 五列全空且无跳转 → `is_code_row=0` 的中间节点（38 行），正常入库。
2. 校验门槛（导入即验，任何一条不过就停下来人工看）：
   - 行数 = 1533；level0 恰 1 行；
   - 每个 `jump_target` 能在本表 `index_name`/`full_index_name` 里找到目标（43 条全解析，0 悬空）；
   - 码格式正则 `^[CD]\d{2}(\.\d)?$|^C\d{2}$`，异常值（如区间码）单独列出。
3. 幂等：按 `seq_no` 全删全插（表小，1533 行）。

## 5. 匹配链路：形态学码 → 动态编码 → 部位码

### 5.1 行为码 → 列映射（ICD-O 动态编码）

| 形态学码行为位 | 语义 | 取列 |
|---|---|---|
| /0 | 良性 | code_benign |
| /1 | 交界恶性/动态未定 | code_uncertain |
| /2 | 原位癌 | code_in_situ |
| /3 | 恶性原发 | code_malignant_primary |
| /6 | 继发恶性（转移） | code_malignant_secondary |
| /9 | 恶性，原发/继发未特指 | 默认 code_malignant_primary（可配置，先按 /3 处理） |

### 5.2 触发点与流程

在 `IcdIndexDiagnosisResolver` 命中索引节点后加一步 `NeoplasmSiteResolver`（纯内存，肿瘤表构建成快照）：

```
输入: 甲状腺C细胞癌
① 现有链路: 主导词 癌 → 下钻 C细胞 → 码 M8510/3（裸形态码，无 :部位）
   子节点含 "特指部位 - 见 肿瘤，恶性"（See 指针）与 "未特指部位 C73"
② 触发条件（二选一即可）:
   a) 命中节点码为 Morphology 且 SiteCode 为空（裸 M 码）
   b) 命中节点的子树里有 "特指部位 - 见 肿瘤…" 指针
③ 行为位 3 → 列 = code_malignant_primary
④ 部位提取: 用输入文本对肿瘤表快照做别名匹配（复用 TextMatch.NormalizeKey +
   括号别名生成），命中候选行；同名行按 父路径覆盖度 消歧:
   - 候选行的 full_index_name 各段词被输入连续覆盖的最深者胜
   - 例: 输入含 喉 时 甲状 取 喉下(C32.3)，只含 甲状腺 时取 1级(C73)
⑤ 输出: 该行列值 C73 → 走现有 IndexCodeExpander 字典展开（C73 前缀 → 甲状腺恶性肿瘤 详码），
   Note 记 "形态学 M8510/3(/3) + 部位 甲状腺 → 肿瘤表·恶性原发 = C73"
⑥ 回退（精度优先）:
   - 输入无部位词 / 部位词在肿瘤表 0 命中 / 多候选父路径无法区分
     → 用索引自带的 "未特指部位" 码（C73），即维持现状行为，不硬猜
   - 索引行本身带 :部位（M8332/3:C73）→ 完全不进肿瘤表（编码员口径：索引直接给部位码就不再查表）
```

### 5.3 指针与符号处理

- 肿瘤表内部 `见` 指针（43 条）在**快照构建期**解析：查询命中指针行时直接重定向到目标节点再取列，与 icd_index 的 See 语义一致；`另见`（1 条 腱膜）保留本行、目标作降权候选。
- NEC/`#`/`◇` 沿用 `ICD索引特殊符号全解析.md` 的既有口径（NEC 参与别名剥离、◇ 部位链扩展、`#` 注释），不新造规则。

### 5.4 与"肿瘤部分被过滤"现状的衔接

- 现在裸 M 码在 `FallbackItems` 里被丢弃；改造后仅在**肿瘤表能给出部位码**时产出推荐，给不出仍走现状（丢弃/未特指码），不引入新的错误推荐面。
- `见 肿瘤，恶性` 从死指针变成可解析跳转，是本次唯一的召回增量来源。
