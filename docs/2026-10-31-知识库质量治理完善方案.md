## 二、完善方案（四个工作包，可分批落地）

### WP-A｜增量行回写入库（治本，最高优先）

**目标**：消灭「库内增量 vs 仓库批次」的 9021 行脱节，让任何环境重装后知识面一致。

1. **导出固化**：把本轮 v5 兜底行（9021 行「诊断名逐字挂码」）+ 历史散落补丁（plastic-site、tumor-site、lost-words v2/v3/v4）合并成规范批次 JSON（`icd-index-batches/batch-9001.json` 起，格式与现有批次一致）；
2. **批次重号校验**：导入前校验 seq_no 不与现有冲突（本轮 v5 用 60007+ 号段）；
3. **manifest 升级为构建产物**：新增 `source-manifest.schema` 字段——`knowledgeVersion`（递增）、`patches[]`（每个补丁文件名+行数+日期）、`diffSummary`（vs 上一版增/改/删计数）；导入端点导入成功后自动回写；
4. **验收**：删库重建 → 导批次 → `SELECT COUNT(1) FROM icd_index` 与 manifest.knowledgeVersion 记录行数一致；跑 IcdIndexDiag --batch 与本轮台账逐名一致（含 27 名流失名全部命中）。

工期：1 天。

### WP-B｜质量巡检命令（治标自动化，中优先）

**目标**：把「重复/笔误/无锚点」从人工发现变成一键巡检，产出可分派清单。

新增 `dotnet run --project tools/HospitalAi.Tools -- kb-doctor`，五项检查：

| 检查 | 逻辑 | 输出 |
|---|---|---|
| 同 title 不同码 | GROUP BY title HAVING COUNT(DISTINCT code)>1 | `kb-issues-ambiguous.csv`（人工裁定保留哪个码） |
| 同码重复行 | GROUP BY code,title HAVING COUNT(1)>1 | `kb-issues-dup-rows.csv`（自动可清） |
| 形近笔误 | title 两两编辑距离 ≤1 且非繁简差异（限同前缀族，控制量级） | `kb-issues-typos.csv`（人工确认） |
| 索引行 vs 字典码互证 | 索引行码在字典无前缀命中（3 个失配码类）/ 字典标题无任何索引可达 | `kb-issues-orphans.csv` |
| E3 无锚点复测 | 对 blank_names 清单重跑 `IcdIndexDiag --blank`，输出仍无锚点清单 | `kb-issues-no-anchor.csv`（补词工作队列） |

巡检结果落 `data/knowledge/reports/kb-doctor-<日期>/`，纳入 git。工期：1.5 天。

### WP-C｜索引行停用开关与审计（中优先）

**目标**：错行「停用」而非「删除」，可回滚、可审计。

1. icd_index / cm3_index / tumor_index 三表加 `is_enabled bit NOT NULL DEFAULT 1` + 迁移；快照/Designer 同步（流程同 LoginLockout）；
2. 快照构建器与消费者过滤 `is_enabled = 1`（Elasticsearch 灌库同步跳过）；
3. 导入端点支持 upsert（同 seq_no 更新而非冲突）；新增 `PATCH /api/v1/knowledge/icd-index/{id}/enabled`（权限挂 KnowledgeIcdUpdate，cm3/tumor 同理）；
4. 停用动作写 audit_log（复用解锁审计模式：resource_type='icd_index'，action='disable'）；
5. 验收：停用「胆总管石痞病」类错行 → 万条台账不变（该行本不在链路）→ 恢复启用 → 台账一致；审计留痕可查。

工期：2 天。

### WP-D｜维护 UI 与批量清洗（体验，中低优先）

**目标**：编码员/知识管理员在页面上完成日常治理，不再依赖 SQL。

1. 知识库页新增「质量问题」页签：读取 WP-B 的 CSV 巡检结果（或改为 API 直查），按类分列表展示；
2. 行内操作：
   - 歧义 title → 选定保留码（其余行停用）；
   - 笔误 → 行内改 title（upsert）或停用；
   - 无锚点 → 一键「加入补词清单」（导出 CSV 供知识工程）；
3. 索引行编辑对话框：改 title/code/停用/启用，全部走 WP-C 的权限与审计；
4. i18n 中英完整；权限复用现有三级树（knowledge.icd.update 等）；
5. 验收：UI 完成一次「停用错行 → 重跑该名 IcdIndexDiag → 链路变化可见 → 恢复」闭环。

工期：2~3 天。
