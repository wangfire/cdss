## 实测口径补记（与方案初稿的差异）

1. 真库中存在以疾病全名作主导词的行（如 0 级行 `中心细胞性淋巴瘤 C83.809`），全量匹配会把它作为最优主导词命中——符合"全量匹配"定义，展示在首位；
2. 同名多 0 级行（两个 瘤）按词面合并展示，链路按 pathKey 去重；
3. `细胞(性) - 另见情况` 是无码行，下钻无可用链路时该主导词只展示词面（"无链路"提示），不产出编码；
4. 证据链重叠门（0.30）+ 回退码殿后两道收敛保证泛词长行（如 `淋巴、造血和有关组织…肿瘤` 靠 淋巴 沾上）不会压过真实字典码。

## 1. 需求

新增一个**录入诊断或手术**的功能：

1. 诊断（ICD-10）与手术（ICD-9-CM-3）均支持两种录入方式：
   - **手动输入**名称；
   - **从字典表选择**（`medical_code` 字典库）。
2. 录入名称后，按名称**拆分出合理的主导词**，再到各主导词下**查找修饰词**，最终**推荐有效编码**。
3. 主导词拆分口径：**全量匹配**（严格子串）——
   - 例：输入 `中心细胞性淋巴瘤`，命中 4 个全量匹配主导词：`中心`、`细胞（性）`、`淋巴瘤`、`瘤`；
   - **不找范围外/部分匹配的主导词**：如 `丘疹病`（词面无交集）、`淋巴瘤样`（输入只含"淋巴瘤"，"样"字超出输入范围）一律不召回。
4. 每个主导词下继续按输入查找修饰词（下钻），产出候选编码，经**字典有效性校验**后推荐。

## 3. 主导词拆分算法（核心新增：`NameLeadTermSplitter`）

### 3.1 输入归一化

- 全角→半角、英文统一小写、去首尾空白；中文词面原样保留；
- 保留 `，/、` 分隔符信息（CM3 "部位，术式" 惯例、ICD "主导词，修饰" 惯例仍可用它做提示，但**不参与全量匹配判定**）。

### 3.2 候选主导词面集合（每系统一份，构建期一次）

取自现有快照，不新查库：

1. `icd_index` / `cm3_index` 快照中 **0 级有效主导词**（`Leads`）的全部别名键（`ParseAliases` 产物：主别名、"或"并列段、方括号别名、去括号变体）；
2. `LeadByExactKey` 的键（含主导词 Term 归一键）；
3. `AnotherNames`（"又称"等价变体）；
4. `icd_term_synonym` 同义词（**默认不启用**，避免召回污染；作为后续可配置开关）。

### 3.3 全量匹配判定（严格子串，一条规则排除全部"范围外"主导词）

```
别名键 k 命中 ⇔ 归一化输入中存在连续子串等于 k（Ordinal Contains）
```

- `丘疹病` 不是 `中心细胞性淋巴瘤` 的子串 → 不命中（词面无交集，范围外）；
- `淋巴瘤样` 不是 `中心细胞性淋巴瘤` 的子串 → 不命中（"样"字超出输入，部分匹配）；
- `中心`、`细胞`/`细胞性`（主导词原始词面 `细胞(性)` 的两个别名变体）、`淋巴瘤`、`瘤` 均为连续子串 → 命中 4 个主导词，与需求示例一致。

不做任何模糊/拼音/语义扩展——主导词召回只有这一条全量匹配规则，天然满足"不找范围外的主导词"。

### 3.4 去重与排序

1. **去重**：同一主导词节点（SeqNo）多个别名命中只保留一条，展示**索引原始词面**（如 `细胞(性)`）+ 实际命中的别名；
2. **排序**（决定展示顺序与后续推荐权重）：
   - ① 覆盖字数（命中别名长度）降序：`淋巴瘤(3)` ≈ `细胞性(3)` > `中心(2)` > `瘤(1)`；
   - ② 同覆盖字数时，命中位置更靠近输入**尾部**者优先（编码惯例：核心主导词多为名称尾词）；
   - ③ 主别名权重（1.0 > 0.85）；
   - ④ 稳定排序保序。
3. **单字主导词**（瘤/疝/裂…）按规则保留参与（示例明确要求 `瘤` 命中），仅排序降权；
4. 默认返回全部全量命中（临床名称通常 ≤ 8 个），接口可传 `topK` 兜底超长名称。

## 4. 修饰词查找与有效编码推荐（`NameCodingLookupService`）

对每个命中主导词执行（复用既有下钻，输入=完整名称）：

1. **修饰词下钻**：`IcdIndexMatcher`（诊断）/ `Cm3ProcedureIndexMatcher`（手术）
   - 门控全部沿用：子节点需"新增长连续段 ≥ 2"、部位/人群限定词须为输入已声明子集、病程极（急性↔慢性）与否定极（非X↔X）不相反；
   - `见` → 改道重查；`另见` → 本地保留并挂提示；`见于/由于` 连接行折叠沿用现口径；
   - 肿瘤形态学/部位场景沿用 `tumor_index` 通道。
2. **编码扩展**：命中链经 `IndexCodeExpander` / `Cm3IndexCodeExpander` 扩展为候选码（X 填充、6 位扩展）。
3. **有效码校验（"有效编码"的口径）**：
   - 候选码必须存在于 `medical_code`（对应 code_system，`is_enabled=true`）才进入推荐；
   - 索引码在字典不存在时，归一到字典中存在的**最细可用父码/类目码**并明确标注"类目码（非细码）"；
   - 一条链路扩不出任何有效码 → 该链路只展示链路不出码。
   - 实现上为每个 code_system 维护一个有效码 `HashSet`（进程内缓存，导入字典后失效重建）。
4. **字典直达**：若输入名称与字典标题精确一致（或用户从字典表选中条目），该码**置顶返回**，主导词拆分结果仍并列展示作为证据。
5. **汇总排序**：跨主导词合并去重（同码取覆盖最优链路）：
   - ① 字典精确名命中 > ② 链路覆盖字数 > ③ 链路深度（修饰词层数）> ④ 主导词排序权重；
   - 返回 Top N（默认 8）。

## 5. 接口设计（新增 1 个，复用 1 个）

### 5.1 名称解析（新增，无状态）

```
POST /api/v1/coding/name-lookup
权限：复用 CodingCaseEntry（编码录入权限）

请求：
{ "kind": "diagnosis" | "procedure", "text": "中心细胞性淋巴瘤", "topK": 8 }

响应（示意）：
{
  "kind": "diagnosis",
  "normalizedText": "中心细胞性淋巴瘤",
  "dictionaryHit": { "code": "...", "title": "..." } | null,     // 字典标题精确命中
  "leadTerms": [
    {
      "seqNo": 12345, "term": "淋巴瘤", "hitAlias": "淋巴瘤",
      "coveredChars": 3, "position": 5,
      "modifierPaths": [
        { "path": ["淋巴瘤", "＊- 霍奇金病", "－－- 结节性淋巴细胞为主"],
          "code": "C81.000x004", "title": "...", "valid": true, "jump": null }
      ]
    }
    // …中心 / 细胞(性) / 瘤
  ],
  "recommendations": [
    { "code": "C81.000x004", "title": "...", "codeSystem": "ICD10",
      "leadTerm": "淋巴瘤", "path": ["淋巴瘤", "霍奇金病", "结节性淋巴细胞为主"],
      "source": "index" | "dictionary", "isCategoryOnly": false }
    // Top N，已按 §4.5 排序
  ]
}
```

- 诊断走 `icd_index` 快照 + `IcdIndexMatcher`；手术走 `cm3_index` 快照 + `Cm3ProcedureIndexMatcher`；
- 不落库、不建任务，纯即时解析（前端可反复试）。

### 5.2 字典检索（复用现有）

`GET /api/v1/knowledge/medical-codes?codeSystem=&keyword=&page=&pageSize=` 已支持按编码/名称/searchText 检索，直接作字典选择弹窗数据源；如实测性能不足再补一个轻量 top-N 搜索端点（备选，不在首期范围）。

### 5.3 结果落库（已确认：确认后可保存落库）

- 确认后的编码走既有落库端点，后端零改动：
  - 整病例（患者+就诊+诊断/手术清单）：`POST /api/v1/coding/case-entry`；
  - 单条最终编码：`POST /api/v1/final-results/submit`；
- 前端在"编码录入"页提供"保存为病例"入口（把已确认条目组装进 CaseEntryRequest）；
- 解析过程本身仍无状态不落库。

## 8. 测试与验收口径

   - `中心细胞性淋巴瘤` → 命中 {中心, 细胞(性), 淋巴瘤, 瘤}，且**不含** `丘疹病`、`淋巴瘤样`；
   - 同一主导词多别名命中去重为一条；
   - 单字主导词（瘤）参与召回。
2. **推荐有效性**：所有推荐码 ∈ `medical_code` 且 is_enabled；扩不出细码时标注类目码。
3. **手术侧用例**：`阑尾切除术`（主导词 `切除术` → 修饰词 `阑尾` → 47.0x 系列有效码）。
4. **字典直达**：输入名与字典标题一致时置顶返回。
5. **端到端冒烟**：起本地环境，前端页面手动输入 → 解析 → 选码全流程走通；回归既有冒烟 `tests/smoke/run.ps1` 确认无副作用（新端点无状态，不影响流水线）。

## 11. 边界与风险

| 风险 | 对策 |
| --- | --- |
| 名称含大量单字核心词（病/瘤/疝…）导致命中过多 | 覆盖字数+尾部位置排序、chips 折叠、topK 兜底 |
| 索引行码 ≠ 字典码（7 种码格式） | Expander 现有逻辑 + 字典校验兜底 + 类目码显式标注 |
| 输入不规范（标点、全半角混排） | 归一化层统一处理，分隔符仅作提示不参与匹配 |
| 双口径漂移（本功能 vs 流水线推荐） | 下钻强制复用同一 Matcher 实例与门控，不另写第二套逻辑 |
| 性能 | 主导词拆分为内存快照上的子串扫描（约 2-3 万别名键 × 输入长度），毫秒级；有效码校验走进程内 HashSet |
