## 一、系统概况

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 API | .NET 8 (HospitalAi.Api) | 编码任务、推荐查询、人工审核、知识库、工作台接口 |
| 推荐流水线 | .NET 8 (HospitalAi.Worker / V2.2-Lite) | 文书解析 → 证据提取 → 检索 → 规则 → 评分 → 推荐落库，全链路可追溯（Trace） |
| 数据库 | SQL Server（HospitalAi） | 任务、输入、候选、推荐、证据、规则、审核结论等全部持久化 |
| 检索引擎 | Elasticsearch 8.14.3 + IK 中文分词 | 知识库约 5.3 万条 ICD-10/ICD-9 编码，BM25 词法检索 |
| 前端 | Vue 3 + Vite（web-ui/admin） | 编码工作台、知识库管理、仪表盘 |
| 多租户 | 请求头 X-Hospital-Id | 所有接口按医院隔离数据 |

## 二、已完成功能

### 1. 平台基础（Phase 1）
- 登录认证、RBAC 权限策略、医院级数据隔离。
- 编码任务管理：任务创建/查询、病案首页文书入库（含入院诊断、出院诊断、手术操作三段结构化内容）。
- 人工审核闭环：接受/修改/拒绝推荐，生成最终编码结论（final_coding_result）；**已确认的推荐受保护，任何自动重跑不会覆盖人工结论**。
- 流水线全程 Trace：每次运行记录各步骤状态、降级标记、质量问题（QualityIssue），可审计回放。
- 数据质量门：文书缺失/内容为空/重复哈希/出入院时间矛盾等在 Step 1 即拦截并给出人话提示。
- 知识库管理界面：ICD 编码浏览与查询。

### 2. AI 编码推荐流水线（V2.2-Lite）
端到端 11 步已跑通并在真实数据上批量验证：
1. 质量门 → 2. 诊断输入解析（四类来源：FRONT_PAGE 首页出院诊断、ADMISSION_PAGE 首页入院诊断、DOCUMENT_AUTO 文书自动抽取、PROCEDURE_AUTO 手术操作自动抽取）→ 3. 临床事实抽取 → 4. 证据链生成（按入院/出院/手术段落定位）→ 5. 精确匹配检索 → 6. BM25 检索 → 7. 向量检索（占位、明确降级）→ 8. 规则引擎 → 9. 模型解释校验（口径就绪）→ 10. 七维评分 + 置信度策略 → 11. 推荐与证据落库（版本化、软失效）。
- 支持 ICD-10 诊断 + ICD-9 手术操作双体系推荐，且**类型严格隔离**（诊断页不出手术码，手术页不出诊断码）。
- 每条诊断输入最多产出 3 个候选编码（宁缺毋滥策略）。

### 3. 编码工作台 UI
- 任务列表：按姓名/病案号搜索，状态页签过滤，当前 601 个任务全量可查。
- 推荐三区页签：**入院诊断 / 诊断（出院） / 手术**，各输入按主诊断/次诊断分组展示候选编码与置信度。
- 证据链悬停面板：每条推荐显示关联原文证据（来源类型、得分、匹配到的标准名称"→"标注），且**入院推荐只引用入院诊断段原文、出院推荐只引用出院诊断段原文**，互不串扰。
- 运行记录抽屉：按任务回放最近 20 次流水线运行（11 步骤耗时、降级标记、质量问题、推荐条数），审计回访可视化。

### 4. 病例录入（补记于当日晚间）
- 新页面"病例录入"：录入病案号 / 姓名 / 住院次数 / 出入院日期 + 入院诊断、出院诊断、手术操作（每行一条）与可选附加文书，一次提交即自动建患者、就诊、文书、编码任务与结构化诊断输入，并**同步跑完 V2.2-Lite 推荐流水线**（单条约 1–5 秒）。

### 6. 本轮修复的匹配质量问题（重点难点）
| 问题 | 根因 | 修复 |
|---|---|---|
| "神经根型腰椎病"推出糖尿病编码 | ES 默认按单字切词，共享"神经根"即高分 | 容器安装 IK 分词（ik_max_word/ik_smart）+ 应用侧连续片段覆盖率门槛 |
| "腰椎退行性病变"推出颈椎/胸椎编码 | 词法相似但部位冲突 | 标题部位限定词必须是输入已声明的子集，否则剔除 |
| 诊断页出现 ICD-9 手术码 | 检索未按体系隔离 | 输入类型与编码体系强绑定 |
| 名称含逗号被误拆两条（"脑血管疾病，其他特指的"） | 分隔符含全角逗号 | 分隔符收敛为 、；。！？ |
| 入院诊断页签大面积为空（234/501） | 入院=出院时被去重吃掉 | 首页入院段结构化为 ADMISSION_PAGE 输入单独入库 |
| 证据链入院/出院串扰 | 证据未按段落定位 | 按文书字符偏移做段区间过滤 + 抽取器位置游标修正 |
| 2 字诊断（咯血/便秘）无出院证据 | 抽取器长度门槛 | 门槛 3→2 并保留叙述句过滤 |

## 三、匹配与推荐规则说明

### 3.1 召回（候选从哪来）
1. **精确匹配（Exact）**：规范化后的诊断名与知识库标准名称/同义词完全一致，直接召回，最高优先。
2. **BM25 词法召回**：Elasticsearch IK 分词，按标题、同义词、检索文本多字段打分；医院维度过滤，编码版本对齐。
3. 向量语义召回：本阶段**未接入**（设计上显式记 DEGRADED.NO_VECTOR，禁止伪分数）。

### 3.2 相关性门槛（防止"看着像"）
候选必须**同时**满足以下条件才保留（精确命中豁免全部门槛）：
- **类型隔离**：诊断输入 ↔ 仅 ICD-10；手术输入 ↔ 仅 ICD-9。
- **糖尿病星码规则**：候选标题含"糖尿病"而输入未提糖尿病 → 剔除（治理 E11.600X015+M14.2* 类复合码污染）。
- **部位冲突规则**：候选标题中出现的部位限定词集合（颈/胸/腰/骶/肩/肘/腕/髋/膝/踝/足/手/头/腹/耳/鼻/牙/眼/角膜/妊娠…）必须是输入已声明部位的子集，否则剔除（治"肩周炎→甲周炎"、"电针→头针"）。
- **连续片段覆盖率门槛（ContiguousCover）**：反复提取标题与输入的最长公共子串（≥2 字）覆盖输入字符，要求
  - 覆盖率 Ratio ≥ 0.6，且
  - 输入 < 3 字，或 最长公共片段 MaxSegment ≥ 3，或 覆盖率 = 1.0（完整覆盖多段拼接标题，如"子宫肌瘤"↔"子宫腺肌瘤"）。
  - 该设计刻意不用二元组(bigram)指标：ICD 标题常重排词序，跨词 bigram 会误杀正确编码（"神经根型腰椎病"↔"腰椎间盘突出伴神经根病"覆盖 0.71 通过；"电针治疗"↔"芒针治疗"0.5 剔除）。
- **条数上限**：每条输入最终保留 ≤3 个候选（精度优先）。

### 3.3 证据链规则
- 证据来源于当前生效文书（DISCHARGE_NOTE），按临床事实抽取，记录字符位置、来源段（【入院诊断】/【出院诊断】/【手术操作】）。
- **段落隔离**：ADMISSION_PAGE/FRONT_PAGE 推荐的证据必须落在对应诊断段字符区间内；段内无证据时回退到"与标题或输入文本直接匹配"的相关证据（不会引用无关原文）。
- 每条推荐证据 ≤3 条，按证据分降序；证据标准名与输入名不一致时 UI 以"→ 标准名"标注匹配关系。
- 叙述性句子（病程/术后/恢复顺利等）、含"诊断"字样的引导句、尾部编码标注均被抽取器过滤。

### 3.4 七维评分（V2.2-Lite 框架）
| 维度 | 权重 | 当前状态 |
|---|---|---|
| Exact 精确 | 0.15 | 已接入 |
| Semantic 语义 | 0.15 | 未接入（置 null） |
| Retrieval 检索 | 0.10 | 已接入（BM25 融合分） |
| Rerank 重排 | 0.10 | 未接入（置 null） |
| Rule 规则 | 0.15 | 已接入 |
| Evidence 证据 | **0.20（最高）** | 已接入 |
| LLM 一致性 | 0.15 | 口径就绪，无模型时置 null |

规则：**缺失维度不填默认值，按实际参与维度重新归一化**；score_profile 记录参与口径，跨口径分数不横向比较。
规则分：PASS=1.0 / WARNING=0.5 / BLOCK=0（BLOCK 候选直接出局并写质量问题）。
LLM 分（如接入）：证据引用有效性 40% + 候选存在于检索 20% + 解释可被证据支持 20% + 无否定/时间违规 20%；模型输出未通过 Schema 校验则不给分。

### 3.5 置信度策略（推荐如何定性）
- **HIGH_CONFIDENCE**：FinalScore ≥ 0.85 且 EvidenceScore ≥ 0.75 且与第二名 Margin ≥ 0.10，且无规则 WARNING、粒度足够、有证据。
- **NEED_REVIEW**：未达高置信（如仅泛化编码 GENERIC 粒度、证据弱）。
- **NO_SAFE_RECOMMENDATION**：无有效证据或全部候选被门槛/规则剔除——**宁可不推，不推错的**。
- 降级透明：ES 不可用（NO_BM25）、无向量（NO_VECTOR）、无模型（NO_MODEL）均显式记入运行 Trace，绝不伪造分数。

### 3.6 数据安全与人工优先
- 旧推荐重跑时软失效（STALE）保留历史，可回溯版本链。
- 已被人工确认（final_coding_result 引用）的推荐**永不被自动覆盖**。
- 全部接口强制医院隔离（X-Hospital-Id），编码串比较用二进制排序防大小写误匹配。

## 四、待完成事项

### 高优先（推荐能力）
1. **向量语义检索接入**：embedding 模型选型与索引建设，补齐 SemanticScore；预期改善同义病名、缩写、口语化书写的召回。
2. **Rerank 精排**：cross-encoder 或规则混合重排，提升 Top1 准确率。
3. **LLM 解释与一致性校验实接**：当前为无模型降级运行；接入后产出推荐解释文本 + LlmScore，提升医生信任度。
4. **否定/时间/确定性事实识别**：RuleEvaluationContext 的 FactNegation/FactTemporality 现为 null，需抽取器支持"排除XX""既往XX"类表述，避免阴性描述被编码。
5. **编码规则库扩充**：现内置规则较少，需临床编码室共建（主要诊断选择、合并编码、星剑号等 ICD 规则的数字化）。

### 中优先（工程与平台）
6. **异步 MQ 链路**：本地 RabbitMQ 端口不规范，目前走同步 `/recommend`；需打通消息驱动 + 失败重试 + 夜间批量。
7. **HIS/EMR 正式对接**：现数据经 SQL 导入脚本，需接口化（含入院/出院诊断结构化的 import_admission_page 逻辑前移到导入侧）。
8. **知识库质量治理**：已发现duplicate标题（中医按摩 93.3907/93.3940）、笔误（"胆总管石痞病"）等，需版本化校对流程与维护 UI。
9. **工作台性能**：任务列表一次性 Take(5000) 客户端过滤，数据量增长后改服务端分页+搜索。

### 低优先（体验与运营）
10. 审核统计报表（推荐采纳率、平均耗时）、导出编码结论、多住院次/多次就诊时间线展示、权限角色细分。
