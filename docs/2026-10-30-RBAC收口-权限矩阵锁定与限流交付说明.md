## 二、正式权限矩阵

### 2.1 内置角色模板（`src/HospitalAi.Application/Security/RoleMatrix.cs`）

平台唯一权威定义，迁移内 SQL 与本定义保持同口径（新增权限码时两处同步维护）：

| 模板码 | 名称 | 授权口径 |
|---|---|---|
| `CODER` | 编码员 | coding.read + coding.review 全量审核按钮（accept/modify/reject）+ coding.caseEntry |
| `DOCTOR` | 临床医生 | coding.read + coding.caseEntry（只读 + 录入，不审核） |
| `REVIEWER` | 病案审核 | coding.read + coding.review（审核功能，不含病例录入） |
| `KNOWLEDGE_MANAGER` | 知识库管理员 | knowledge.read/write + 全部知识库按钮（icd/cm3/tumor/synonym 增删改 + 四类导入 + 建院 + 索引重建） |
| `USER_ADMIN` | 账户管理员 | user.manage/create/status/role.assign + role.create；**刻意不含 role.permission 写权**，避免「只授账户管理」的角色自行改写角色权限形成提权闭环 |

`ADMIN` 固定全权不落库（既有语义不变）。

### 2.2 存量环境收敛（迁移 `20261030091000_SeedRoleMatrix`）

- 幂等回填：对每家医院，凡模板码角色已存在则补齐缺失的模板权限（只增不改，不动人工配置的其他权限）；
- 旧阶段角色码 `COLLECTOR` 不在模板内，不回填，由管理端人工收敛；
- Down 不删数据（无法区分「模板补齐」与「人工配置」），语义说明写入迁移注释。

### 2.3 角色创建套用模板

- `CreateRoleAsync`：同码内置角色创建即自动带模板权限（人工可再收敛）；
- 前端「新建角色」弹窗新增模板一键套用区（预填 code/name/description，显示各模板权限数）；
- 模板查询端点：`GET /api/v1/security/role-templates`（要求 UserAdmin 策略）。

## 三、登录锁定（防暴力破解）

### 3.1 行为

1. 密码错误：连续失败计数 +1；**达到阈值的那次失败直接返回 HTTP 423 Locked**，让用户立刻知道已锁定；
2. 已锁定：即使密码正确也在密码校验前拒绝（423），错误体 `data.remainingLockoutMinutes` 携带剩余分钟数；
3. 成功登录：失败计数清零并解除未过期的锁（不累积锁定）；
4. 解锁：管理员 `POST /api/v1/users/{userId}/unlock`（user.status 权限），清零计数并解锁；
5. 配置：`Security:Lockout`（默认 5 次失败锁 15 分钟；阈值 ≤0 可整体关闭）。

### 3.2 持久化（迁移 `20261030091000` 前置的 `20261030090000_LoginLockout`）

`app_user` 新增三列：`failed_login_count int`（计数）、`locked_until datetimeoffset(7) NULL`（锁定截止）、`lockout_at datetimeoffset(7) NULL`（最近触发时间，审计用）；`locked_until` 建非聚簇索引。模型快照与 Designer 文件已同步。

### 3.3 错误体映射（`ExceptionHandlingMiddleware`）

`AccountLockedException` → **423 Locked** + `ErrorResponse(code: "locked_error", data: 剩余分钟数)`，其余 `DomainException` 仍走 400，不影响既有语义。

## 四、登录限流

- ASP.NET Core RateLimiter，`login` 策略：**按客户端 IP 分区的固定窗口**（`X-Forwarded-For` 首段优先，回退 `RemoteIpAddress`），默认 60 次/60 秒（`Security:RateLimit`）；
- 超限返回 **429 TooManyRequests**；仅 `/api/v1/auth/login` 挂载；
- 分层防线：限流挡 IP 级刷接口，登录锁定挡账号级暴力破解；医院内网 NAT 场景窗口额度按科室并发登录峰值放宽，由锁定兜底；
- 未配置/阈值为 0 时不注册限流中间件（保持旧行为，便于本地联调关闭）。
