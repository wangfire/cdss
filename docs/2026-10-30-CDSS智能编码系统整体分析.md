## 0. 结论摘要

**项目是什么**

面向医院病案编码场景的 CDSS（临床决策支持）系统：把病案首页/出院记录中的诊断与手术名称，映射为 ICD-10 / ICD-9-CM-3 标准编码，给出候选、置信度、证据链，由编码员人工确认后形成最终编码。系统按"一套架构、三期建设、一期闭环"推进：Phase 1 智能编码推荐 → Phase 2 全病历质控 + Agent 分析 → Phase 3 平台治理。

**现在在哪**

Phase 1 已完成**工程闭环 + 院内真实数据验证**，正在做**精度收口与生产化收口**；Phase 2 尚未启动。系统在本机可完整演示：登录 → 病例录入/任务受理 → Worker 异步流水线 → 工作台推荐与证据 → 人工审核 → 最终编码，全链路可追溯。

**四个关键事实**

| 维度 | 当前状态 |
|---|---|
| 工程完整度 | 6 个后端项目、6 个前端页面（含登录/账户）、约 70 个 `/api/v1` 端点、36 张表、20 个 EF 迁移、308 个测试用例；CI 覆盖后端构建/测试与前端构建 |
| 编码能力 | 诊断侧为 ICD 索书两段式 + 字典标题直达/反查 + 向量补位；手术侧为 CM3 索引两段式 + 标题直达；向量与 Rerank 为真实 ONNX 推理；LLM 网关已实接但默认关闭 |
| 精度水平 | 万条诊断名 L0 编码级 Top1 约 **27.5%**、类目级 Top1 约 **43.8%**（2026-10-24 在线轮）；手术临床名面 Top1 **97.72%**（2026-10-24 离线轮，输入接近字典标题） |
| 生产就绪 | 认证/RBAC/医院隔离/异步任务/降级标记已具备；生产部署编排、密钥管理、登录防爆破、前端生产化、HIS/EMR 对接尚未完成 |

**最大缺口（按影响排序）**

1. **验收口径尚未最终裁定**：决策 3 的 25%/50% 验收线挂 L0、L1 还是新建 L5，规范 §7 仍待拍板；最近一轮 caliber 未提供 `--attribution`，E3 未剔除，严格冻结口径下的 L1 数字缺失，不能正式宣布"达标"。
2. **类目级精度仍差临门一脚**：在 10-24 的宽 L1（n=7906）下类目级 48.44%，距 50% 差约 1.6 个百分点；剩余错码集中在 C（肿瘤）、S（部位扩展码）、R（症状）、I（内科排序）四章。
3. **LLM 维实际未参与精度**：默认 `ModelMode=Unavailable`，0.5B 模型无法稳定引用证据，LLM-on 还会带来约 −79 的排序税；当前验收数字均为 LLM-off。
4. **生产化最后一公里**：无生产 compose/k8s、TLS、密钥管理、备份监控；JWT Key 仍是占位符；前端地址写死 localhost、通知为 mock、导入无文件上传、工作台客户端分页；CI 未覆盖前端类型检查、冒烟、迁移校验与万条回归。

## 1. 项目目标

### 1.1 总目标

依据 V2.2 基线，系统要成为医院内网、本地数据、本地模型、本地知识库的编码辅助决策平台，必须遵守八条原则：

1. AI 推荐 ≠ 最终编码；
2. No Evidence, No Coding；
3. 硬规则优先于模型判断；
4. 推荐必须可解释、可追溯；
5. 人工确认结果优先级最高；
6. AI 不确定时允许拒答；
7. Agent 只能产生候选建议，不得直接写 Final Coding；
8. Model / Prompt / Knowledge / Rule / Coding Version 全部可追溯。

### 1.2 三期业务边界

| 阶段 | 定位 | 核心内容 | 当前状态 |
|---|---|---|---|
| Phase 1 | 智能编码推荐 | 病案接入、文档解析、事实与证据、混合检索、规则引擎、模型网关、候选与推荐、人工审核、最终编码、Trace、基础 Feedback | 主体完成，精度与生产化收口进行中 |
| Phase 2 | 全病历智能质控 | 文档完整性、临床逻辑、编码逻辑、主要诊断、诊断排序、集合级 QC、DRG/DIP 风险、分级审核、RECODING | 未启动；基线预留了数据结构 |
| Phase 2 | Agent 智能分析 | Orchestrator、Skill Registry、Tool Calling、多轮推理、高风险触发、Human Handoff、12 个质控 Skill | 未启动 |
| Phase 3 | 平台治理 | A/B、灰度、多模型路由、知识/规则治理、高级 DRG/DIP、多医院多租户、成本优化、知识图谱 | 未启动 |

## 2. 总体架构

### 2.1 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 API | .NET 10 Minimal API | 认证、RBAC、业务端点、Swagger、健康检查 |
| 推荐流水线 | .NET 10 Worker + RabbitMQ | Outbox 落任务、Worker 异步消费、V2.2-Lite 流水线 |
| 数据 | SQL Server + EF Core 10 | 任务、候选、推荐、证据、规则、索引、审核结论持久化 |
| 检索 | Elasticsearch 8 + IK 分词 | 字典 BM25；ICD/CM3/肿瘤索引走 SQL 快照 |
| 向量/重排 | ONNX Runtime（CPU） | bge-small-zh-v1.5 + bge-reranker-base，线程配额 4 |
| LLM | Ollama `qwen2.5:0.5b-instruct`（可选） | 默认关闭，走 OpenAI 兼容网关 |
| 前端 | Vue 3 + Vite + tabtab-ui | 工作台、病例录入、知识库、账户权限、仪表盘 |
| 可观测 | OpenTelemetry + Serilog | HTTP/SQL/MQ/流水线指标；无生产 collector/告警 |
| 部署 | Docker Compose（仅 dev） | 无生产编排、TLS、密钥管理与备份 |

```text
病例录入 / SQL 导入 / API 建任务
        │
        ▼
coding_task + outbox_message ──MQ──▶ Worker
        │                              │
        │                              ├─ QUALITY_GATE
        │                              ├─ DOCUMENT_CHUNK
        │                              ├─ FACT / EVIDENCE
        │                              ├─ 输入解析（入院/出院/手术）

        │
        ▼
人工审核 ACCEPTED / MODIFIED / REJECTED ──▶ coding_final_result
```

### 3.4 评分与置信度

七维权重：Exact 0.15、Semantic 0.15、Retrieval 0.10、Rerank 0.10、Rule 0.15、Evidence 0.20、LLM 0.15。

- 缺失维度不填默认值，按实际参与维重新归一化，`score_profile` 记录参与口径；
- HIGH_CONFIDENCE 要求 FinalScore ≥0.85、EvidenceScore ≥0.75、与第二名 Margin ≥0.10，且无规则 WARNING、粒度足够、有证据；
- 不满足则 NEED_REVIEW；无有效证据或全部候选被剔除则 NO_SAFE_RECOMMENDATION；
- 降级透明：NO_BM25 / NO_VECTOR / NO_MODEL / NO_RERANK / NO_CM3_INDEX 均写入 Trace，不伪造分数。

### 3.5 证据链与人工审核

- 证据来自当前生效文书，记录字符位置、来源段（入院/出院/手术），按段区间隔离；
- 每条推荐最多 3 条证据，按证据分降序；输入名与标准名不一致时 UI 显示"→ 标准名"；
- 叙述句、引导句、尾部编码标注被抽取器过滤；
- 审核三动作 ACCEPTED / MODIFIED / REJECTED 各有独立权限码；
- 已确认推荐受保护，重跑只做软失效，不覆盖人工结论。

### 4.2 万条诊断名精度演进

口径说明：JZEY 医院、`JZEY测试-` 患者前缀、10,000 个去重诊断名，对照源库 `DiagnosticSet_LCZD`。L0 为全部名称不剔除；L1 为剔除 E1–E5 后的可判定范围（冻结口径 n=6760）。

| 日期 / 口径 | 有推荐 | 编码级 Top1 | Top3 | 类目级 Top1 | 备注 |
|---|---|---|---|---|---|
| 2026-09-30（L0） | 67.1% | 14.0% | 16.9% | 26.1% | 纯索引通道基线 |
| 2026-10-20（L0） | 100% | 27.67% | 37.14% | 43.62% | 向量通道出数 + 索引规则累计 |

| 2026-10-24（宽 L1，n=7906） | 100% | 30.15% | 40.15% | 48.44% | 未提供 `--attribution`，E3 未剔除，**不等于冻结 L1** |
| 2026-10-26（离线索引通道，开标题直达/反查） | 7900/10000 | 26.54% | 32.12% | 44.73% | 仅 ICD_INDEX 通道；关断基线 Top1 20.92% |

**怎么读这张表**

- 编码级 Top1 从 14.0% 提升到 27.5%，已经越过 25% 的验收线；类目级从 26.1% 提升到 43.8%，仍未到 50%。

- "有推荐 100%"主要来自向量补位，不等于判对；10-20 归因显示向量贡献了 Top1 净增的 61.6%，其中约 487 条是"索引完全无产出"时的纯补位。

### 4.4 LLM 维

| 轮次 | 编码级 Top1 | 类目级 Top1 | 结论 |
|---|---|---|---|
| LLM-off（10-08 基线） | 1395（L0） | 2605 | 验收口径基准 |
| LLM-on（10-09，0.5B） | 1390（−5） | 2625（+20） | 排序扰动 16.1%，净收益接近零 |
| LLM 判据改造后（10-16） | 在线索引通道 Top1 1969 vs 离线 2048 | — | 排序税约 −79 |

- 当前默认 `ModelMode=Unavailable`，不发起 LLM 调用；验收数字均为 LLM-off；
- 0.5B 模型无法稳定引用证据（`cited_evidence` 恒空或恒填固定编号），证据引用维实际拿不到分；
- LLM-on/off 不可直接比较，必须作为独立基线另发，并以 `score_profile` 自证参与维。

### 4.5 "达标"结论

**不能宣布 G4 达标**，原因有三：

1. 验收线挂哪一层尚未拍板（规范 §7 的 A/B/C 三选一）；
2. 最近一轮 caliber 的 L1 是宽口径，冻结 L1（n=6760）没有 10-24 之后的官方数字；
3. L4 人工抽查 20/50 例未执行，自动口径缺少人工校准层。

**可以宣布的阶段成果**：编码级 Top1 已从 14.0% 提升到 27.5%，手术临床面全通道 97.72%，诊断标题直达/反查与 CM3 直达均为可开关、可 A/B、硬线可复算的工程化能力。

## 6. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 口径漂移 | 向量/LLM 通道开关、容器启停都会改变数字；同一份代码可给出 14%–31% 的不同 Top1 | 发布必须带 L0/L1/L2、LLM-on/off、ALL/ICD_INDEX/VECTOR 拆分；固定语料与脚本 |

## 9. 总结

这个项目已经完成"从 0 到 1"的主体建设：Phase 1 的编码推荐闭环、真实数据验证、索引/向量/重排三类召回、证据链与人工审核、知识库与权限体系、离线诊断工具与分层验收口径都已落地，并且形成了"改动必须过硬线、发布必须标口径"的工程纪律。

当前它不是一个"未完成品"，而是一个**能力已具备、验收未签字、生产化未收口**的系统：

- **能力面**：诊断编码 Top1 约 27.5%，手术临床名面 97.72%，索引通道覆盖约 74%–79%（视轮次），向量补位把在线有推荐率拉到 100%；
- **验收面**：类目级 43.8%/48.4%（取决于分母）仍未到 50%，严格 L1、L4 人工校准、验收层归属三件事没有闭环；
- **工程面**：CI、RBAC、异步任务、降级标记已具备，生产部署、密钥、前端生产化、HIS/EMR 对接仍缺；
- **产品面**：Phase 2 的全病历质控与 Agent 分析尚未开始，这是下一阶段的主战场。

因此，近期最值得投入的不是再堆一条匹配规则，而是：**先把口径与人工校准闭环，再用 C/S/R/I 四章的定点补词与排序把类目级推过 50%，最后完成生产化最后一公里**。完成这三步，Phase 1 才具备"可验收、可试点、可交付"的完整含义。
