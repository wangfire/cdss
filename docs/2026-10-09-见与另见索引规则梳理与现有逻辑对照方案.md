## 1. 规则整理（编码员口径）

### 1.1 "见" 的两种

**见-1　见 + 另一个主导词 → 必须转换。**
索引行本身不给可采用的码，指针就是命令。

```
42    β脂蛋白血症，宽或上浮                        E78.2
43     －过度 - 见 高β脂蛋白血症
11918 高β脂蛋白血症(家族性)                        E78.0
```
"β脂蛋白血症过度" 不能停在 42 行的 E78.2，必须转到 `高β脂蛋白血症` 取 E78.0。

**见-2　见 + 情况 → 该主导词选错了，须按情况重选主导词。**

```
15829 会阴的 - 见情况        （失效主导词，lead_word_status=1）
```
"会阴撕裂" 用 `会阴的` 当主导词不成立，要按情况重选（`撕裂，撕裂伤` → 会阴 → S31.0）。
补充口径（本次已实现）：**见情况 / 另见情况 是在所有主导词都找不到了，才到【病，疾病、疾患】主导词下匹配。**

库里规模：含"见情况"的行 **592** 条，含"另见情况"的行 **141** 条。

### 1.2 "另见" 的两种

**另见-1　另见 + 关键词（甚至一级修饰词），且本行带编码。**
- 病案信息简单（信息全在这条诊断里）→ **直接采用本行编码**；
- 病案信息更详细 → **必须转到推荐主导词**，那里有更细的情况码；这一步也是发现"诊断漏填修饰词"的唯一途径。

```
切开术
 9846  －剖宫产(另见 分娩，剖宫产)          O82.9      ← 简单：剖宫产分娩 = O82.9
分娩，剖宫产（推荐主导词下才有细码）
        －－瘢痕 → 宫颈                     O34.4
        －－瘢痕 → 剖宫产 / 子宫            O34.2
        －伴子宫切除术                     O82.2
        －产程延长 NEC                     O63.9
        －额先露                           O32.3
        －宫缩乏力 → 原发性/继发性          O62.2 / O62.1
```

**另见-2　另见 + 关键词，本行无编码，但下面的修饰词带编码。**
先在本树判"满足哪一种情况"；没有合适修饰词时，按推荐的另一个关键词另查。

```
HIV - 另见 人(类)，免疫缺陷病毒[HIV]病
  －对婴儿的非结论性试验                   R75
  －实验室证据(非结论性)                   R75
  －阳性，血清反应阳性                     Z21        ← "HIV阳性" 走这里
```

### 1.3 通则
见 / 另见 推荐的主导词下，一般有更详细的诊断修饰词与编码 → 改道结果在信息量上优先于本行的泛化码。

## 2. 现有实现口径（代码事实）

| 环节 | 现状 |
| --- | --- |
| 行解析 | `JumpRegex` → `IndexJumpKind.See / SeeAlso / Redirect`；`IsValidLead = None 或 SeeAlso`，即 level-0 的"见"行不是主导词，进 `snapshot.Redirects` |
| 召回期改道 | 仅当该文本变体 **一个主导词都没召回**（`leadHits.Count == 0`）时，用 `inputKey` 精确命中 `Redirects` 重试一次 |
| 下钻期"见" | 记为 `pendingJump`；末端与本地链路**并列取优**，判据：`跳转链路覆盖输入字符数 ≥ 本地覆盖数` |
| 下钻期"另见" | 记为 `pendingSeeAlsoJump`；须同时满足 (a) 下钻停在该节点 (b) 本地无自码或只能祖先兜底 (c) 跳转结果非祖先兜底 |
| 泛词指针 | 目标首段 ∈ {情况, 疾病, 病} 的 见/另见 → 只登记不下钻；整轮常规链路 0 产出时才到 `病，疾病` 子层精确锚定（本次改造） |
| 取码回退 | 链上无码 → 最近有码祖先（`CodeFromAncestorFallback`）→ 主导词码 → 三级回退 `IsIndexFallback` |

## 3. 矛盾点逐条

### M1　见-1 的"必须转换"被覆盖数比较否决 —— 与规则直接冲突

`β脂蛋白血症过度`：本地链路终点是 43 行（**本行无码**），靠祖先兜底拿到 E78.2；跳转链路 E78.0 的
覆盖字符数按代码判定式是 6（输入没写"高"，"家族性"也不在输入），本地是 8 → 条件 `jumped ≥ local` 不成立，改道被放弃。

规则视角：43 行既然标了"见"，编码员根本不会考虑 E78.2；**祖先兜底码不该拥有和本行自码同等的对抗资格**。
现有的覆盖数比较是为另一类问题加的（"阻塞(性)" 下 `器官或部位,先天性NEC -见 闭锁` 靠虚字符挣增益，不得劫走 J44.9），
不该把"本行无码、只能回退祖先"的情形一起保护掉。

拟改：`见 + 具体主导词` 时，若本地结果 `CodeFromAncestorFallback`（终点无自码），跳转结果**无条件优先**；
只有本地终点**自带编码**时才继续比覆盖数。跳转增益 ≥1 且来自输入实词的前置条件保留。
风险：中。命中面是"祖先有码 + 子行标见"的链路，需专门加 2 条单测（β脂蛋白 正例 / J44.9 反例）。

**实现口径（已落地）**：跳转结果在本地终点 `CodeFromAncestorFallback`（本行无码、只能回退祖先）时无条件优先，
本地终点自带编码才继续比覆盖数。基线 `offline_batch_after2.tsv`，台账 `offline_batch_m1b.tsv`：
Top1 口径 **+5 / -2**、Top3 **+5 / -1**、`becameEmpty 0`、`becameFilled 1`。
-2 的两条是 `右足部开放性损伤 S91.301→S91.300X823`、`胫神经麻痹 G57.401→G56.201`
（同族近邻码换位，不是从有到无）。首版 `offline_batch_m1.tsv` 曾把 3 条只有裸三级码
（`T14.2`、`R53`）的输入打成空推荐，改为"裸码不参与改道比较"后归零。

### M2　level-0 的"见 具体主导词"触发条件过严

`剖腹产 - 见 剖宫产`、`神经硬化 - 见 疾患，神经` 这类行不是主导词，只能走 `Redirects`，
而 `Redirects` 只在**整条输入零召回**时才查。输入里只要还有别的词召回成功（如"剖腹产瘢痕子宫"里的 瘢痕），
强制改道就被跳过 → 与见-1"必须转换"冲突。

拟改：把 `Redirects` 按目标分两类——
- 目标含 情况/疾病/疾患 → 维持末位兜底（见-2）；
- 目标是**具体主导词** → 视为该词的唯一合法主导词：命中该失效词即改道，且改道结果排序不低于同输入的其他链路。
风险：高（会压制其他链路），建议先在 500 条抽样上验证再上万条。

**实现口径（已落地）**：没有采用"改道结果排序不低于其他链路"的加权方案，而是把目标主导词的链路
**平权放进常规候选池**一起比分（不加权、不压制，`权重 1.0`，与常规召回同树时跳过），
证据链写 `[跳转: 剖腹产 → 剖宫产]`。实测（基线 `offline_batch_m4.tsv`，台账 `offline_batch_m2c.tsv`）：
L0 有推荐 6497→**6519**、Top1 口径 1439→**1445**、Top3 1755→**1761**、类目 Top1 2621→**2627**，
L1 同向（+6/+2/+2/+2），`top1Lost / top3Lost / becameEmpty` **全 0**；
原始集合层面只有 29 条输入被触碰（新增 37 个候选、移除 2 个），Top1 换位 2 条
（`胸膜浸润 E32.800 胸腺疾病 → J90.X00X002 渗出性胸膜炎`、`沃辛瘤` 见下）。
加权方案的风险在实测里被证实：万条里 173 条补位中有 250 条 Top1 被改写，故否决。

三道精度门控（每道都是先复算出真实损伤再加的，台账 `offline_batch_m2.tsv` / `_m2b.tsv` / `_m2c.tsv`）：

- **目标为泛词的不走本通道**（`IsGenericConditionTarget`）：`X -见 情况` 属见-2，仍是末位兜底，不能当具体主导词改道。
- **失效词本身是泛化段的不走本通道**（复用召回层黑名单 `IsGenericLeadKey`）：
  `43487 新生儿 -见 母体情况` 说的是人群段，放行后 `新生儿黄疸` Top1 由 `P57.900` 变 `P00.900`。
- **两字失效词只有"输入主体就是它"（整条 ≤4 字）才够格**：`马尾神经损害` 里的 神经 是通道构成成分，
  放行会把正确的 `G83.400` 顶成 `S34.300`；同形输入 `马尾神经`（4 字）仍正常改道出 `S34.300`。

第四条门控是本轮最意外的一条：**"或"式并列别名拆出的裸泛词尾段不得当失效主导词**。
`36770 斯托克斯-亚当斯病或综合征 –见 阿-斯综合征` 按 `或` 拆别名后产出键 `综合征`，它进了 `Redirects`
却不携带病种信息；放行后 **7 条** 输入（`眩晕综合征可能性大`、`烟雾综合征I期`、`肾病综合征并急性肾功能衰竭`、
`腔隙综合征,其他的`、`贲门撕裂综合征 失血性休克`、`心律失常-病态窦房结综合征 房颤`、
`原发性干燥综合征伴间质性肺病`）被注入 `I45.901/I45.900X011`，其中最后一条把正确码
**`M35.000 干燥综合征` 挤出过 Top3**。落地为 `IsGenericConditionWord`（族词 情况/疾患/综合征/病，疾病 一律不改道）。

已知残留（未在本轮处理）：`22074 淋巴瘤性乳头状囊腺瘤[沃辛瘤] -见 肿瘤，涎腺，良性` 的跳转目标带逗号，
`ResolveJumpLead` 只按首词 `肿瘤` 锚定，没有沿 `肿瘤 → 涎腺 → 良性` 续钻，结果给了 `D44.800 多发性内分泌腺瘤`
（改造前是 `C73.X00` 甲状腺，同样错）。属跳转目标解析的独立缺口，万条只此 1 条，先记账。

### M3　另见-1 的"信息更详细必须转"未实现

**落地时先暴露一个更底层的缺口**：库里 `另见` 行共 **2785** 条，其中 **2409** 条写成结尾圆括号形式
（`－剖宫产(另见 分娩，剖宫产)`），而 `JumpRegex` 只认 "横杠/空格 + 见/另见"，括号形态一条都解析不出来
——指针既留在词面里污染别名与覆盖度计算，也让 另见-1/另见-2 全部无从触发。
这 2409 条里 **2342 条本行自带编码**，正是 另见-1"病案信息简单直接采用本行编码"的形态。
因此 M3 分两步：先让 `ParenJumpRegex` 认出括号指针（只认 `另见`，不认 `见`，
以免把 `－肾小球(见于)`、`结膜炎(见于)(由于)` 这类尾巴误判成指针），再在本地自码链路上挂提示。

现规则"本地已有自码绝不被另见劫走"在 `剖宫产瘢痕子宫` 上表现为：Top1 给了 `瘢痕→子宫 N85.801`，
`分娩，剖宫产` 树里的细码（O82.2/O34.2）没有作为"应改道"的信号出现，编码员看不到"漏填修饰词"提示。

拟改（保守，不改 Top1）：另见目标树若有更细命中，作为**并列候选进 Top3**，证据链显式写
`本行 O82.9 为直接采用码；更详细情况见 分娩，剖宫产 → 瘢痕 → 宫颈 O34.4`。
这与既有"精度优先、空推荐好过错推荐"的取向一致，只补可见性。
风险：低（只动 Top3 与证据文案）。

**实现口径（已落地）**：`DrillResult.SeeAlsoHints` 携带跳转树链路，三个触发条件缺一不可——
链路**终点行**自带编码（`!CodeFromAncestorFallback`）、终点行自身带 `另见` 指针
（`ReferenceEquals(current, hintChild)`）、指针树按同一输入又走出**不同**且非祖先兜底的细码
（`alt.CodeNode.Code != local.CodeNode.Code`）。Note 写
`本行 {直接采用码} 为直接采用码，更详细情况见 {跳转链路} {细码}`。Top1 与既有排序不受影响。

两条实测出来的纪律（都进过万条回归）：

- **"本行" 必须等于链路终点**。`pendingSeeAlsoJump` 只记录"层内第一个挣到增益的 另见 兄弟"，
  不加等值判断时 `右下肢动脉栓塞` 会用兄弟行 `36408 冠状(动脉或静脉)(全身性) -另见 梗死，心肌` 出题，
  把 `心肌梗死 I21.9` 塞进外周动脉候选：**125 条**输入 Top3 被改写，其中 **46 条**注入了 I21.900。
- **满额只补空位，不让位**。同一条 指针链路两种放法的万条对比（基线 `offline_batch_m5.tsv`）：

  | 放法 | Top1± | Top3口径 | 既有条目被挤掉 | becameEmpty | 新增补位输入 |
  | --- | --- | --- | --- | --- | --- |
  | 只补空位（`offline_batch_m3f.tsv`，已采用） | 0 | +2 | 0 | **0** | 2 |
  | 末位让位（`offline_batch_m3e.tsv`，已否决） | 0 | +3 | 20 | 0 | 2 |

  让位只多换到 1 条口径命中，代价是把 指针树里的另一个部位 顶进候选——
  `梗阻性黄疸 急性胆囊炎 胆囊结石` 挤掉 `K80.200X003` 换成 `Q44.300 先天性胆囊缺如`、
  `肘关节创伤性关节病` 挤掉 `M19.101` 换成 `S53.100X031 肘关节扭伤`。按"精度优先"取前者。

### M4　泛词族只认 `病，疾病`

`IsGenericConditionTarget` 认 情况/疾病/病，`ResolveJumpLead("情况")` → 疾病 → 2972。

## 8. 或尾段锚点判据（2026-10-10，输入 左乳腺结节 的跨行噪声）

问题：主导词 结节 的推导是对的，但候选里同时出现 `施莫尔病或结节 → M51.400` 与
`赫伯登病或结节(伴有关节病) → M15.100`。链路是 `ParseAliases` 按 `[或，、]` 把
"A病或B" 拆成并列别名（尾段权重 0.85），尾段 结节 与头段一样进 `RecallLeads` 当锚点；
这两行本身带编码，而输入挣不到任何下钻增益（施莫尔/赫伯登 不在输入里），
`Drill` 就停在主导词行返回自码——于是人名行的码被"疾病通用名"借走了。
0 级行里 "病或X" 式共 140 条，尾段 骨软骨瘤/综合征/发作 同理会跨行锚定。

判据（`IcdIndexSnapshotBuilder.Build`）：**某 0 级行的 或 尾段键，若已是另一 0 级行的头段
（权重 1.0）别名，则该尾段在本行不得独立作召回锚点**（`IcdIndexAlias.RecallAnchor=false`）。
