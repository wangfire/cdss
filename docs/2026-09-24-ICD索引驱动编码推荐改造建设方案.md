# ICD 索引驱动的两段式编码推荐改造建设方案

> 日期：2026-09-24 ｜ 状态：已确认（§12 三项决策已拍板，见文末） ｜ 分支：codex-phase2-coding-mvp

---

## 1. 背景与目标

### 1.1 现状

当前智能编码工作台的推荐链路（`V22LiteCodingPipelineRunner` Step5 Exact + Step6 BM25）是：

```
医生临床名称 → 归一化/分词 → 直接匹配 medical_code 字典（ICD-10 诊断 / ICD-9-CM-3 手术）标题
```

`icd_index`（ICD 索引库，51268 行）目前只服务于知识库管理端浏览，**没有参与推荐**。

### 1.2 目标

改造为符合 ICD-10 索引检索规范的两段式查找：

```
① 索引树查找：临床名称 ──分词──▶ 匹配有效主导词(level=0) ──parent_seq_no──▶ 逐级匹配修饰词 ──▶ 索引编码
② 编码格式解析：按 7 种索引编码列值格式（单值/†*/:/;/@/范围/空值）确定展开策略
③ 字典回查展开：按策略到 ICD-10 / ICD-9-CM-3 字典中匹配详细编码+名称
   └─ 展开不到 → 回退推荐 ①② 得到的索引编码
```

示例（黄金验收用例）：

```
输入：阿尔茨海默病引起痴呆(老年型)
主导词：阿尔茨海默病或硬化 (G30.9, seq=65)
一级修饰词：引起痴呆 (G30.9† F00.9*, seq=69)
二级修饰词：晚期发病(老年性) (G30.1† F00.1*, seq=71)
② 格式解析：†/* 联合 → 病因 G30.1 + 表现 F00.1
③ 字典展开：code LIKE 'G30.1%' AND code LIKE '%+F00.1*'
   → G30.100X002+F00.1* 家族性阿尔茨海默病性痴呆(老年型)
   → G30.100X003+F00.1* 阿尔茨海默病性痴呆(老年型)
```

## 2. 数据事实（已核验，方案立论基础）

| 事实 | 说明 |
|---|---|
| `icd_index` 列 | `seq_no / raw_name / raw_name_en / index_name / index_code / index_level(0~6) / parent_seq_no(0=无父) / full_index_name($ 分隔路径) / lead_word_status(0=有效,1=失效)` |
| 主导词规模 | level=0 且有效的行 6832 个，可全集常驻内存 |
| 层级表达 | `index_name` 行首 `－` 个数 = 层级，与 `index_level` 冗余一致；父子靠 `parent_seq_no` |
| 索引编码 7 种格式 | 空值 5790(11.3%)、单值 41537(81.0%)、†/* 联合 2572、冒号 M:C 791、分号替代 148、@ 条件联动 122、范围(.- 或 X-Y) 308 —— 见《ICD索引编码列值格式全解析.md》 |
| 字典联合码存储形式 | `medical_code` 中星号码存为 `前码+后缀*`，如 `G30.100X002+F00.1*`、`A01.000X003+G01*`；**† 符号不落库**（含 `*` 的 1564 条，含 `†` 的 0 条） |
| 字典无 M 码 | ICD-10 库 36662 条中 M 码 0 条、C 码 2108 条 → 冒号格式只能展开 C 码，M 码原样保留在索引层推荐 |
| 大小写陷阱 | 字典存 `G30.100X002` （大写 X），库 collation 大小写不敏感，精确比较须 `CAST AS varbinary`（既有约定） |
| 失效重定向行 | 如 seq=75「阿耳茨海默 - 现译名 阿尔茨海默」`lead_word_status=1`，不做召回目标，但可作译名别名索引 |

参考规范：
- `docs/superpowers/konwledge/ICD索引特殊符号全解析.md`（词条内符号：－、()、[]、见、另见、†*、NEC）
- `docs/superpowers/konwledge/ICD索引编码列值格式全解析.md`（编码列 7 种格式与判定优先级）

## 4. 阶段①：主导词匹配与逐级下钻

### 4.1 词条预处理（加载时一次性）

- `index_name` 剥离行首 `－`、尾部编码 → 得纯词干；
- 主导词多别名拆分：`A或B`、`A，B` → 主别名 A、次别名 B（次别名命中降权 0.85）；
- `[...]` 内别名提取为召回用同义词（不参与编码判定）；
- 圆括号三用途标注：澄清词（可剥离但保留原文供修饰词匹配）、内嵌见/另见、形态学 M 码；
- 识别 `- 见 X` / `- 另见 X` 及目标文本（目标为"脓肿，肝，阿米巴"式逗号分段）。

### 4.2 分词与主导词召回

沿用"分词在 ES(IK)、判定在内存"格局：

- 新增 ES 索引 `icd_index_leadwords`：仅 level=0 且有效；字段（均 ik_max_word/ik_smart）：主导词中文名、别名列表、英文名；
- 临床输入 BM25 召回 Top-K（K=8，可配置）候选主导词；
- 内存复核：复用 `ContiguousCover` LCS 覆盖度门控（Ratio≥0.60 且 MaxSegment≥3；主导词完整包含于输入则直通满分）；
- **降级路径**：ES 不可用时，6832 主导词常驻内存做子串/LCS 匹配，结果一致、仅损失召回口味差异。

### 4.3 逐级下钻算法

对每个命中主导词：

1. 一次性加载整棵子树（`parent_seq_no` 递归，子树典型 <200 行，缓存）；
2. 维护"未消费输入 token 集"；从 level=1 逐层对本层子节点匹配（同 4.2 门控；`伴有/见于/由于/的` 等虚词进停用表）；
3. 命中 → 记录节点、其词干从输入中消费、进入下一层；同层多命中取覆盖度最高；本层无命中 → 停在当前最优；
4. **取码**：最深命中且 `index_code` 非空的行；命中链上无码节点（纯分类节点如"－－－伴有发病"）→ 回退最近有码祖先 → 最终回退主导词码；
5. 精确度排序：具体修饰词码 > NEC 码 > 主导词未特指码；
6. **见/另见**：命中 `- 见`（本行必无有效码）→ 解析目标主导词（逗号分段在主导词全集定位）→ 重走 4.2~4.3，跳转上限 2 次 + 环路保护；`- 另见` → 本行结果保留，同时把目标主导词加入候选集（降权）；
7. 输出：`ResolvedIndexCode { indexCode 原样(含 † * : ; @ -), fullPath=full_index_name, matchedNodes, score }`，每输入 ≤3 个。

## 5. 阶段②：索引编码格式解析（IndexCodeFormatParser）

按《格式全解析》§三的优先级对每个 `indexCode` 归类，产出统一结构 `ParsedIndexCode { format, parts[], pairMode }`：

| 优先级 | 判定 | 格式 | 解析结果 | 下游展开策略（§6） |
|---|---|---|---|---|
| 1 | 编码为空 | 已在①跳转/回退处理 | — | 不应到达③；防御性回退主导词码 |
| 2 | 含 `@` | 条件联动（触发码@附加码） | [T=主码(可再含 .-/X-Y), A=附加码] | T 按单值/范围正常展开推荐；本轮推导结果集中存在 T（含范围命中）时才附加输出 A，A 不得单独输出 |
| 3 | 含 `;` | 替代编码组 | N 个候选（每个可再含 †*） | 用输入 token 对各候选做类型/药物/亚型匹配**选 1**；选不出 → 回退主导词未特指码。禁止全量输出 |
| 4 | 含 `:` | M码:C码 | [M码, C码] | C 码进 ICD-10 字典展开；M 码字典无对应（已核验 0 条），原样随索引推荐保留 |
| 5 | 含 `†`/`*` | 病因+表现联合 | [†码, *码]（分号组内可嵌套） | §6 联合码展开 |
| 6 | 以 `.-` 结尾 | 未特指亚型 | 类目根（如 N04） | 前缀 `N04.%` 展开 + 修饰词精排，无门控命中则取 N04 下未特指位 |
| 6' | `X-Y` 范围 | 编码区间 | [起, 止] | 区间内前缀展开（≤10 类目），仅当输入有可定位信息才展开，否则按范围端点原样推荐 |
| 7 | 其余 | 单值 | 1 码 | 前缀展开 + 精排 |

要点：
- 解析器**纯函数**，7 类全覆盖 + 嵌套（`;` 内嵌 `†*`、`@` 侧带 `.-`）都有单测用例；
- †/* 永远成对输出（两个码进推荐记录，中间态用 `+` 连接与字典存储形式 `G30.100X002+F00.1*` 对齐）；@ 附加码为**条件输出**，仅当触发码已进推荐集才追加。

## 6. 阶段③：字典回查展开（DictionaryExpander）

体系路由：诊断输入 → ICD-10；手术输入 → ICD-9-CM-3（复用 `IsProcedureCodeSystem`）。SQL 预筛 + 内存判定（现有模式），字符串比较加 `CAST AS varbinary` 复核。

| 格式 | 候选 SQL（内存再精确判） | 精排 |
|---|---|---|
| †/* 联合 | `code LIKE '†码%' AND code LIKE '%+*码'`（本例 G30.1% + %F00.1*） | title/searchText × (原始输入+下钻各级修饰词) LCS；无联合码 → 退回 † 码单码前缀展开 |
| 单值 / 类目根 | `code LIKE '码%'`（如 `G30.9%`、`K80.0%`） | 同上 |
| @ 条件联动 | T 按单值/范围展开；A 按单值展开 | T 进入推荐集且与 A 同源行 → A 附加输出（受 Top3 约束，优先级低于 T） |
| M:C | C 码前缀展开 | M 码作为索引层证据保留 |
| 替代组(;) | 选 1 后按该码走单值/联合 | — |
| X-Y 范围 | 区间各端点前缀 | — |

**精排门控**（全部复用现成件）：`ContiguousCover` 0.6/MaxSegment3、`HasBodyPartConflict`、`IsUnjustifiedDiabetesCompound`、类型隔离；Top `MaxCandidatesPerInput`=3。

**回退（fallback）三级**：
1. 联合展开为空 → 单码前缀展开；
2. 字典展开整体为空（该索引码在字典无对应范围）→ **直接推荐索引编码本身**，title=`fullIndexName` 路径，`recallChannel=index_fallback`；
3. 阶段① 连主导词都没命中 → 诊断输入不推荐（决策 2，方案 B；仅失效重定向/译名别名可重试一次）；手术输入走 legacy_dict 通道（决策 1）。

## 7. Runner 集成与推荐落库

- 新步骤序：`…EVIDENCE → INDEX_RECALL → INDEX_DRILLDOWN → CODE_FORMAT_PARSE → DICT_EXPANSION → RULE → SCORE → POLICY → PERSIST`，原 EXACT/BM25 两步入参字典的召回按 §8 处理；pipeline step 审计记录逐步骤落库，含耗时与命中数；
- `coding_recommendation` 增加 `recall_channel` 列（一次 EF 迁移）：`index_expanded / index_fallback / legacy_dict`；
- `RecommendationEvidence` 存完整链路：主导词 → 各级修饰词 → 索引编码(格式类型) → 字典编码，前端证据区自然展示，工作台/病例录入页无需改版；
- 三个入口（`/recommend` 同步、`case-entry` 同步、Worker MQ）共用 Runner，全部自动生效。

## 8. 老链路的去留（已拍板：方案 B）

- **诊断输入**：主导词未命中即不推荐（仅可经失效重定向/译名别名重试一次），**彻底删除字典直匹配路径**（Exact/BM25→medical_code 召回对诊断输入不再生效）——符合"精确优先、宁缺毋滥"原则；
- **手术输入**：暂无 ICD-9-CM-3 手术索引库（后续提供），**手术通道维持现有字典直匹配不变**，按输入类型路由：手术→legacy_dict，诊断→索引两段式。手术索引导入后，手术通道切换到同一索引链路并删除 legacy_dict。

## 9. 性能与运维

- 主导词全集（6832）+ 子树缓存：IMemoryCache，跟随 icd-index import 完成后失效重建；
- 单输入开销预估：ES 召回 1 次 + 子树 SQL 1~2 次 + 字典候选 SQL ≤3 次，同步 `/recommend` 场景毫秒级可接受；
- 配置项进 `V22PipelineOptions`：`LeadWordTopK=8`、`IndexJumpMax=2`、`EnableLegacyFallback`（按 §8 决定）。

2. **集成**（Worker.Tests，仿 `V22LitePipelineTests`）：
   - 黄金：`阿尔茨海默病引起痴呆(老年型)` → `G30.100X002+F00.1*`、`G30.100X003+F00.1*`；

## 12. 决策记录（2026-09-24 已确认）

1. **手术侧**：暂无 ICD-9-CM-3 手术索引数据，手术输入本期**维持现有字典直匹配**（`recall_channel=legacy_dict`，仅手术通道保留）；后续手术索引库到位后切换为同一索引链路并删除该通道。（→ §8）
2. **老链路去留**：**方案 B** —— 诊断输入的字典直匹配彻底删除；索引未命中即不推荐，仅允许失效重定向/译名别名重试一次。（→ §8）
3. **"另见"跳转**：放 P2；P1 只做强制"见"改道，"另见"仅作降权候选；"见"改道后目标主导词仍未命中则该诊断输入不推荐。（→ §4.3、§10）
